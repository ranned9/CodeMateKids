# CodeMateKids AI 老师对话与学习记忆开发文档

## 1. 首版目标与交付范围

学生打开「AI 小老师」即可用自然语言提问。老师能结合当前积木、任务目标和刚才的交流理解「这里」「这样可以吗」「还是没懂」等不完整的表达，必要时追问一句。学生修改积木或重新运行后，可以接着聊。换题或下次回来时，老师根据该学生的学习记录选择教学方法，并根据新的表现继续调整。

首版面向当前 Windows 本机 Web 工作台和 `demo-loop` 课程，覆盖「让角色走四步」「小海龟走六步」「让海龟画正方形」三个任务。使用现有网页模型适配器生成对话，使用现有 Runner 和课程标准判定任务表现，以 SQLite 保存本地档案及学习观察。真实模型用于验收自由提问，本地回复用于缺少模型配置或调用失败时继续练习。 [本机运行方式](run.md) · [课程定义](../content/demo-loop/course.json) · [网页模型接入文档](CodeMateKids_网页模型接入与教学Agent开发文档.md)

## 3. 学生界面与对话生命周期

### 3.1 对话面板

- 打开「求助」后，面板依次显示消息列表、输入框和「发送」。移除用于选择教法的「轻提示」「更多提示」「换个例子」「我想自己试」等按钮。学生可以直接说这些话，跳过任务的操作移到课程导航，继续复用现有反馈记录。
- 初次打开时显示「有哪一步想一起看看？」从积木区进入时，在输入框旁显示「当前积木」及其名称。发送时捕获该积木，服务端检查它是否属于提交的积木快照。
- 发送后立即追加学生消息和等待状态。回复追加在其下，教学动作名称、提示等级和诊断信息放入可展开的详情。可以执行的「定位积木」「回放」随相应回复出现，学生控制播放或编辑。
- 使用表单提交。回车发送，Shift+Enter 换行，中文输入法组字期间回车交给输入法。前端去除首尾空白，输入长度沿用 300 字。回复使用纯文本渲染，新增内容用 `aria-live` 通知，输入焦点留给学生。
- 一个工作区同一时间有一条待回复消息。等待期间可继续编辑并输入下一句。网络失败时在原消息旁提供重试，复用原轮次 ID 和请求快照。当前工作区已变化时，由学生发起基于新快照的提问。

[现有面板结构](../frontend/index.html) · [前端 API 封装](../frontend/js/api.js) · [积木选中状态](../frontend/js/state.js)

### 3.2 程序修改、换题和换人

| 事件 | 界面行为 | 服务端归属 |
| --- | --- | --- |
| 修改积木、撤销或完成一次新运行 | 聊天留在当前面板。旧回复的定位或回放失效，晚到的同工作区回复标记为基于先前的积木或运行。 | 对话继续使用当前工作区。最新回复只用本轮快照陈述当前事实。 |
| 切换题目、重开题目或打开作品 | 开始新的工作区。切换时走原有未保存确认和运行终态等待流程。 | 新工作区发起新对话，可读取当前学生在相关知识点上的长期观察。 |
| 切换学生 | 顶栏先确认工作区切换，再清理当前对话、预测和运行显示，进入新学生的练习。 | 每个请求保留发起时的学生归属。旧请求的晚到回复、运行结果或汇总只属于原学生。 |
| 刷新页面或重启服务 | 重新进入工作台，按所选档案继续练习。 | 长期学习观察可恢复。短期对话随工作区生命周期结束。 |

前端区分两次检查。追加消息要匹配学生、工作区和本次提交序号。启用定位、回放还要匹配课程版本、程序版本和指定运行 ID，并确认积木仍可定位。课件更新或模型配置变更时复用现有失效检查。 [页面上下文](../frontend/js/core/viewContext.js) · [工作区切换](../frontend/js/workflows/workspace-change.js)

## 4. 接口契约与学生归属

### 4.1 本地学生档案

顶栏提供「当前学生」，首次选档案或创建档案，后续在同一浏览器标签页刷新时从 `sessionStorage` 恢复选择。学生可使用昵称。服务端生成随机 `studentId`，昵称重复时仍是独立档案。首版信任本机同源工作台操作者，任一操作者可在该工作台切换本机档案。服务继续绑定回环地址，复用现有本机同源检查。 [同源检查](../backend/api/security.py) · [本机启动脚本](../run_demo.cmd)

| 方法与路径 | 请求 | 成功响应中的 `data` |
| --- | --- | --- |
| `GET /api/v1/students` | 无 | `students: [{studentId, displayName}]` |
| `POST /api/v1/students` | `{displayName}`，去除首尾空白后为 1–24 字 | `{studentId, displayName}` |
| `POST /api/v1/tutor/chat` | 下节定义 | 本轮回复和允许展示的操作 |
| `GET /api/v1/students/{studentId}/progress` | 可选 `courseId`，默认当前课程 | `{studentId, courseId, observations, updatedAt}`，供学生进度和验收读取 |

档案 ID 通过 `X-CMK-Student-Id` 随聊天、旧辅导、预测、反馈、总结和运行 JSON 请求传递。保留原生 `EventSource`，运行事件 URL 通过 `studentId` 查询参数传递相同的非凭据标识。服务端校验档案存在，并在运行摘要、事件流和取消入口核对该运行所有者。取消仍须验证现有 `cancelToken`。运行提交时把档案和课堂会话写进 `RunContext`，Runner 回调使用该归属。客户端把学生 ID 随请求或运行捕获，轮询恢复和取消遵循同一份归属。

显式选择「临时练习」或旧客户端省略档案头时，使用临时会话。新聊天临时会话的当前证据按工作区读取。显式传入无效档案返回 `STUDENT_NOT_FOUND`，界面重新打开档案选择。旧接口继续接受原有请求体，原有共享会话仅服务旧调用路径。新档案从首次已归属活动积累观察。 [现有接口](api-contract.md) · [运行路由](../backend/api/routers/runs.py) · [运行上下文](../backend/service/run.py) · [课堂会话接口](../backend/api/routers/session.py)

### 4.2 聊天请求与回复

沿用 `{ok, data, error}` 包封。请求字段如下。消息发送时由前端生成 `turnId`。学生直接回答上一轮追问时可以带 `replyToTurnId`，自由提问始终可以另起一轮。

| 字段 | 约束与用途 |
| --- | --- |
| `taskId` | 当前任务。必须与课程、工作区范围和已提交程序相符。 |
| `message` | 1–300 字。以去除首尾空白的文本作为请求内容。 |
| `learningContext.scope` | 必填，复用 `courseId`、`contentVersion`、`taskId`、`workspaceId`。 |
| `learningContext.turnId` / `replyToTurnId` | 当前轮次必填，所回复轮次可选。沿用现有标识格式。 |
| `learningContext.program` | 有工作区积木时提交当前快照。程序处于编辑中时，使用服务端确认的校验问题或可用结构事实。省略时只使用课程目标和对话背景。 |
| `learningContext.runRequestId` / `predictionId` | 可选。服务端核对档案、工作区和程序摘要，再决定能否作为本轮运行或预测证据。 |
| `learningContext.seenHintIds` / `workspaceSource` | 复用已呈现的提示标识和工作区来源。省略时按证据不完整处理。 |
| `selectedBlockId` | 可选。选中积木的提示线索，由服务端从当前快照解析。 |

以下请求发生在学生和老师刚比较过前进次数与总步数之后。学生没有选中积木，也未提供运行 ID。此轮可以用对话背景澄清指代。

```json
{
  "taskId": "main",
  "message": "那个数字为什么不一样？",
  "learningContext": {
    "scope": {
      "courseId": "demo-loop",
      "contentVersion": "1.3.0",
      "taskId": "main",
      "workspaceId": "task-demo-1"
    },
    "turnId": "turn-42",
    "seenHintIds": [],
    "workspaceSource": "task"
  }
}
```

服务端用结构化字段返回动作，界面显示自然语言。

```json
{
  "ok": true,
  "data": {
    "requestId": "tutor-3841",
    "turnId": "turn-42",
    "message": "你问的是重复积木里的数字，还是海龟一共走了几步？",
    "action": "ask_question",
    "awaitingAnswer": true,
    "supportLevel": 0,
    "hintId": null,
    "controls": [],
    "mode": "model",
    "fallbackReason": null
  }
}
```

`supportLevel` 为 `0–3`，描述给到的帮助程度。非零且确实提供了本题帮助时才签发 `hintId`，供前端呈现后回报。操作项首版为 `{type: "locate_block", blockId}` 或 `{type: "replay", runRequestId}`，由后端从已核对的事实解析。前端使用提交时的快照再次校验。 `mode` 声明实际回复来源，回退类别以固定枚举返回。 [现有 DTO](../backend/api/dto.py) · [提示账本](../backend/session/teaching_store.py)

### 4.3 重试与失败

| 情况 | 处理 |
| --- | --- |
| 同一工作区用相同轮次 ID 重试同一请求 | 返回缓存回复，或在原请求尚未完成时返回 `409 TUTOR_TURN_BUSY`。重试不得形成重复学习观察。 |
| 轮次 ID 已用在不同请求上 | 返回 `409 TUTOR_TURN_CONFLICT`。请求指纹包括规范化消息、回复轮次、积木快照、所选积木、运行 ID、预测 ID 和提示回报。 |
| 被回复的追问已过期或来自另一工作区 | 按自由提问处理，只读取当前工作区的历史。缺少指代时请学生补充一句。 |
| 模型未配置、超时、输出校验失败或配置在调用中更新 | 返回本地上下文回复，保留可核对的事实和匹配的操作。界面低调标注回复来源，失败详情留在诊断中。 |
| 课程版本变化 | 复用 `COURSE_VERSION_UNSUPPORTED`。刷新课程后，新工作区使用当前课程事实和相容的知识点观察。 |
| 学习存储不可用 | 档案列表或进度读取返回 `503 LEARNING_STORE_UNAVAILABLE`。服务进程已解析的档案可用当前课堂会话继续辅导和运行，界面提示进度暂不可保存。无法解析档案时提供临时练习入口。 |

模型对话超时复用现有调用预算。对话保留最近 6 轮供模型参考，另保留最近 32 个已完成轮次的幂等回执，工作区闲置 30 分钟后回收。单工作区最多一个在途模型请求，过期或容量回收时优先回收空闲工作区。幂等回执仅在保留期内有效，前端在工作区或程序已经切换时引导学生按当前情况重新提问。

## 5. 理解问题与生成教学回复

### 5.1 组装本轮证据

1. 解析档案和当前课程 Bundle，校验任务及工作区。读取任务目标、预测题和教学配置。组装程序结构时沿用 `validate_snapshot`、`digest_program` 和 `structure_facts`。积木还在调整时提供已确认的校验问题，允许老师询问或解释。
2. 根据本轮积木和选中标识判断「这里」指向哪里。匹配当前程序摘要的运行才能说明海龟实际做了什么。程序已更新时，上一轮运行可以用「刚才那次」引用，操作控件仍须匹配当前快照。预测使用现有匹配规则，区分对应当前程序的预测和编辑前的预测。
3. 加入同一工作区最近的学生消息、老师追问和教学动作。读取与本题知识点相关的少量结构化学习观察。对话历史提供指代线索，课程和 Runner 提供事实，跨题记录只影响教法。
4. 在一次模型调用里理解学生意图并生成回复。可用动作包含澄清、解释、提示、类比、分步和停止指导。验证到具体积木或回放时再提供相应动作。课程关键词仍可作为线索，短句不再凭关键词判为跑题。
5. 校验回复形状、动作权限、可引用事实和儿童可见文案，再转成界面消息与操作。事实引用复用现有占位符机制，扩展来源到已校验的积木结构。无法核实的运行数据用澄清或解释补上缺口。学生原话及课件文本作为模型输入材料处理。

[积木和运行证据](../backend/service/teaching.py) · [现有决策引擎](../backend/tutor/engine.py) · [模型输出校验](../backend/tutor/chat_adapter.py) · [回复守卫](../backend/tutor/guard.py)

### 5.2 判断何时追问

| 学生输入与当前场景 | 首版回复策略 |
| --- | --- |
| 选中了「重复」积木，问「这里是干嘛的？」 | 直接解释这块积木，邀请学生想想循环体里的动作会怎样反复执行。 |
| 上一轮请学生把「前进」放进循环，改完后问「这样呢？」 | 检查最新版结构。确认放置位置后，可请学生预测下一次运行。 |
| 刚才同时比较过前进次数和总步数，学生问「那个数字怎么不一样？」 | 追问一句「你指的是前进次数，还是一共走了几步？」 |
| 回答「后面那个」 | 用紧邻的追问解析为总步数，继续教学。 |
| 尚未运行，学生问「为什么没有动？」 | 检查可执行链路和可确认的积木问题。证据不足时问「你已经点过运行了吗，还是在猜它会怎么动？」 |
| 学生独立提出明确的问题，前一轮仍有待回答的追问 | 先回答学生当前提出的问题，按需在以后重新核对原来的疑点。 |
| 学生说「我想自己试」或「还是没懂，直接讲一下」 | 前者简短回应并停止追加提示，后者直接讲概念或刚才那一步，沿用现有整题解法约束。 |

### 5.3 回复风格与事实验证

每次回应围绕学生当下的问题展开。直接讲解、给一个提示或问一句都可以结束一轮。学生已经明确表达困惑时承接问题，连续用过同一种提示且结果仍相同时换方法。简单问题优先用一到三句，例子指向当前任务里的具体现象。模板接管时也应根据当前积木、运行证据和尚待澄清的对象给出对应回应。

新聊天定义自己的结构化模型输出，包含 `message`、`action`、`targetRef`、`awaitingAnswer`、`factIdsUsed` 和可选的观察建议。后端按当前证据生成允许的动作及各动作的帮助程度，模型在范围内选择表达及目标。单纯澄清和回应「我想自己试」为零级，点出线索为一级，定向讲解或演示为二级，拆解和局部示例为三级。老师提出可以接续的问题时，后端才确认 `awaitingAnswer`。真实次数、步数、角度由事实占位符生成，概念性讲解可以用经审核的示例。缺少事实、不适用的动作、未经核对的位置及不合格文案转入本地回复。

动作名优先复用 `ask_question`、`explain`、`hint`、`analogy`、`break_down`、`partial_example`、`point_to_block` 和 `show_execution`。聊天新增 `stop_guidance` 表示学生打算自己试。只有定位和回放动作带 `targetRef`，它引用后端事先给出的目标，例如 `selectedBlock` 或 `verifiedReplay`。界面操作中的真实标识由后端填充。

## 6. 学习记录与教学调整

### 6.1 课程知识点与观察来源

课程已经定义 `kp.loop`。在三个任务的 `teaching` 下新增可选的 `knowledgePointIds`，首版均关联 `kp.loop`。课程加载时验证引用存在，旧任务缺省时仍能正常聊天和运行。观察复用课程现有错因，例如 `prediction_mismatch` 和 `action_outside_loop`，在教学策略中区分理解循环结构与区分步数、移动次数这两类具体问题。跨版本读取观察时按课程和稳定知识点 ID 定位，原始证据保留产生时的课程版本。知识点含义改变时采用新的 ID。 [课程定义](../content/demo-loop/course.json) · [课程校验](../backend/service/course.py) · [课程 Schema](../schemas/course.v1.json)

| 时机 | 记录内容 | 写入条件 |
| --- | --- | --- |
| 运行结束 | 是否达到目标、是否满足结构要求、错因、预测是否与本次程序对应及是否正确、帮助状态。 | 由 Runner 终态生成。一条运行只写一次。超时、取消、崩溃保留为运行状态，学习进展规则跳过这些结果。 |
| 推荐的提示已呈现 | 教学动作以及提示程度，可用于判断后续尝试是否接受过帮助。 | 前端可见后纳入 `seenHintIds`，下一次聊天或运行上报。服务端确认提示确实发给该学生和工作区，首次确认才入库。 |
| 学生解释自己的想法 | 模型可提取预定义的观察类型，例如混淆总步数与前进次数，或用自己的话区分两者。 | 本轮聊天归属已确认，观察建议经过白名单检查。将其作为调整本轮和后续教法的线索，可被新的解释或任务证据修正。 |
| 在新任务独立完成 | 在新的任务工作区完成目标，且本次帮助记录为 `none`。 | 有工作区归属和完整的提示回报，程序来源为课程任务。结合精确匹配的正确预测或经过核对的解释，才能提高对相关知识点的判断。 |

现有 Runner 已捕获检测到的提示、预测匹配和执行结果。运行受理时冻结本次帮助状态。提示已确认后，服务端按整个练习工作区保留帮助状态，滚动的前端 ID 列表仅用于确认新增提示。恢复作品或证据不完整时标为 `unknown`。请求发出后才展示的提示影响后续运行，已受理的那次保留原先状态。正方形题按课程现有路线与程序结构要求判定完成。 [运行结束与证据写入](../backend/service/run.py) · [帮助状态和提示确认](../backend/session/store.py) · [正方形事实](../backend/service/teaching.py)

### 6.2 持久化与读取

建议在 `backend/session/student_store.py` 管理档案和 SQLite 连接，在 `backend/session/learning_store.py` 管理观察与查询。增加可配置的 `CMK_LEARNING_DB_PATH`，默认指向本机 `data/learning.sqlite3`，忽略数据库及其伴随文件。数据库使用短事务，`PRAGMA user_version` 管理 schema，迁移完成后再提供档案读写。使用标准库 `sqlite3`。

| 表 | 主要字段 |
| --- | --- |
| `students` | `student_id` 主键、`display_name`、`created_at`。 |
| `learning_observations` | `student_id` 外键、`course_id`、`content_version`、`task_id`、`workspace_id`、`knowledge_point_id`、`source_type`、`source_id`、`kind`、`details_json`、`observed_at`。 |

- 观察使用 `(student_id, course_id, task_id, knowledge_point_id, source_type, source_id, kind)` 唯一键防止重跑写入流程造成重复。来源 ID 分别使用运行请求 ID、已确认提示 ID、学生消息轮次 ID。并发运行结束时按稳定 ID 写入，读取按观察时间加主键稳定排序。
- `details_json` 只存受约束枚举、布尔和必要的数字，例如 `pattern`、`support`、`predictionMatch`、`predictionCorrect`、`outcome` 和 `action`。长期记忆不需要原始聊天、完整程序或模型凭据。临时聊天、运行快照和定位信息按现有或前述工作区时限回收。
- 知识点查询按学生、课程、知识点和时间索引。每次回复最多读取当前知识点最近 12 条观察，优先使用最近一次有关的任务结果。强证据来自真实练习及可核对的解释。新旧线索冲突时把结论留给本轮验证。
- 每个并发操作使用所属线程的连接和游标。一次运行的多个知识点写入同一事务，写入异常不阻塞现有运行终态。只记录脱敏错误类别，恢复后的新证据照常保存。数据库初始化失败时保留临时练习入口，并提示学习进度暂时不可用。
- 学生昵称只用于本机界面。发送给模型的上下文包含当前所需的课题事实、经过筛查的近期消息、匿名化的观察摘要和允许的动作。复用现有儿童信息筛查，对明显的个人信息转本地回复。日志保留请求 ID、耗时、回复来源、动作及回退类别。 [模型入口和日志投影](../backend/api/routers/tutor.py) · [日志字段](../backend/infra/logging.py)

### 6.3 选用教法的规则

按顺序应用表中的条件。当前事实始终限制可执行动作。当前学生明说要自己试时结束提示轮次，等待他主动提问。学生直接要求讲解时，优先简短地解释概念或他正在问的步骤。

| 条件 | 选用教法 | 下一次用于核对的证据 |
| --- | --- | --- |
| 指代不明，两个解释会引出不同的帮助 | 只问一个能分辨两者的问题。 | 记住追问及候选的指代，接续「前面那个」「是」等回答。 |
| 当前答案或错误明确，首次出现 | 解释可验证的事实，给一个可执行的提示。 | 学生的解释、修改或下一次预测。 |
| 两次可比较的完成运行出现相同错误，且学生已经看过同类提示 | 改用另一种方式。混淆步数和前进次数时优先使用已核对的回放。积木放错位置时定位到当前积木。 | 学生能否说出区别，或在后续运行中更正相同问题。相同快照的原样重跑合并为一次练习机会。 |
| 在帮助下完成 | 确认具体进展。下道相近题先请学生自主预测或解释。 | 新题的预测、结构及帮助状态。 |
| 新题有独立完成与正确预测等相互支持的证据 | 将轻提示放在明确求助之后，优先引导学生自己检查结果。 | 若新题再次卡住，按当前问题恢复适量帮助。 |
| 线索相互矛盾、缺少匹配运行或只剩历史观察 | 用当前题的可确认事实提出一个小验证。 | 依据新的回答和运行结果更新观察。 |

教法选择由 `backend/tutor/engine.py` 中可单测的策略负责。输入包含当前意图、已验证事实、近期动作和知识点观察。输出包含建议动作、允许的动作和目标、提示力度及选择原因。使用带实际练习结果的证据调整默认力度，单次猜中、单次任务通过或学生自评会影响本轮交流，长期教法要有后续证据支撑。

### 6.4 跨题示例

学生林林在「走四步」中说「我把海龟每走一步算作前进一次」。老师展示回放，让他看到执行一块「前进」和走过的总距离是两回事。林林修改积木后达到目标。数据库保留对话线索、已确认的回放帮助和本次成功的运行记录。

第二天林林打开「走六步」，学生问「这个要怎么算？」。老师先带他看「每次前进」的设置，再让他预测这块积木会执行几次。学生先给出正确预测，然后独立运行达标。下一次进入迁移题时，老师把更多判断留给林林。如果林林又混淆动作次数和步数，老师可回到观察和解释。另一位学生打开同一题，从自己的记录开始。

### 8.2 人工验收流程

1. 创建两个学生档案。用第一个档案在「走四步」尚未运行时选中重复积木，问「这里是什么意思？」。确认老师可以直接解释。
2. 把重复次数设为三次、每次前进两步，完成一次运行。先请老师指出前进次数和总步数，再问「那个数字为什么不一样？」。确认老师会先问正在看的数字。输入「后面那个」，确认老师能接着解释。
3. 按提示修改积木，继续输入「这样呢？」并重新运行。检查对话连续、旧操作失效、新操作只引用当前运行。让第一个学生通过回放后完成任务。
4. 用第二个学生档案独立完成「走四步」和「走六步」，在「走六步」给出与最终运行对应的正确预测。分别查看两份进度，确认第一个是「有帮助完成」，第二个有两道题的独立完成和「走六步」的正确预测证据。
5. 停止并重启本机服务，分别用两个档案打开「走六步」。第一个学生求助时，老师先确认对步数与前进次数的理解。第二个学生遇到相似情境时，老师鼓励他先用自己的方法检查。让两个学生继续回答或操作，再确认老师根据各自最新表现改变帮助。
6. 完成「画正方形」的迁移题。用同一路线的展开版本和单一循环版本分别运行，确认老师能区分路线正确和循环结构达标。关闭网页模型再走一遍提问与回放，确认本地回复能继续课堂。

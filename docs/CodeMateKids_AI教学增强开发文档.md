## 1. 目标与交付条件

孩子先预测，运行后观察差异，在老师的提示下只改一处并复验，最后在新情境中尝试独立使用循环。AI 老师根据本次程序、预测和运行事实选择下一步。分层提示、积木定位和课堂总结沿用现有工作台入口。

| 交付条件 | 可观察结果 |
| --- | --- |
| 老师能区分错因 | 在「走 6 步」中，重复次数偏少、前进在循环外、每次走得太短分别得到不同提示。每条提示引用相符的事实 |
| 老师会更新判断 | 孩子看完提示后改一处、重新预测并运行。新结果决定下一步，旧的积木定位和回放随工作区变动失效 |
| 孩子能看懂执行过程 | 可逐步查看前两轮，区分「动了几次」和「一共走了几步」 |
| 孩子能尝试迁移 | 「画正方形」校验循环结构和舞台结果，课后总结呈现本次迁移使用的帮助 |
| 演示稳定 | 默认本地辅导可走通全流程，超时、取消、缺失轨迹和模型回退都有可操作的提示 |

本期使用 `kp.loop` 和单机内存会话。条件、变量、账号、长期学习档案、家长端、自动生成课程和自由聊天列入后续范围。教学验收以可复现的课堂场景为准，教育成效需另行验证。

## 3. 课堂流程与课程配置

### 3.1 任务顺序

| 任务 | 孩子看到的目标 | 预测与观察 | 完成标准 |
| --- | --- | --- | --- |
| `main` 让角色走四步 | 让角色一共走 4 步，试试用重复积木 | 先猜角色会动几次。运行后对照次数、总步数和循环内积木的执行 | 沿用原过关条件，累计走 4 步；另行记录循环是否实际执行 |
| `variant` 小海龟走六步 | 让小海龟走 6 步，试着每次走 2 步 | 先猜移动次数，再通过回放观察「一轮走 2 步」 | 沿用原过关条件，累计走 6 步；结束语仍为可选加练 |
| `transfer-square` 画正方形 | 让海龟沿着四条边走回起点。每条边用一块前进积木走 2 步，再转一个直角 | 先猜整个程序会执行几次前进。看到前进与转弯重复组成一条边 | 累计 8 步、前进 4 次、回到起点且朝向复原，并且前进和转弯在同一个循环内 |

正方形任务的初始程序提供「当开始」积木，孩子自行组合重复、前进和转弯。提示入口保持可见，默认推荐先试一次。任一任务可跳过并从任务列表返回。走四步完成后推荐走六步，走六步完成后推荐画正方形，画正方形完成后推荐学习总结。推荐任务不存在或不可进入时，显示学习总结或其他可进入任务。

### 3.2 课程内容字段

在 `course.v1.json`、`backend/service/course.py` 和课程响应中支持以下可选字段。课程包更新时递增 `contentVersion`，保留现有课程主版本与作品格式。

| 字段 | 用法 |
| --- | --- |
| `nextTaskId` | 推荐的下一题。`main` 可沿用 `variantTaskId`，`variant.nextTaskId` 指向 `transfer-square`。加载时检查目标存在、非自身、导航无环 |
| `teaching` | 可选对象。`goalKind` 取 `distance` 或 `square`；`suggestedStepsPerMove` 用于步数题的引导，须为积木支持范围内的正整数，且能整除该题唯一的 `stage.steps eq` 目标 |
| `programCriteria` | 可选数组，本期仅接受 `square_single_repeat`。关联 `teaching.goalKind=square`，由后端解释，课程配置只填枚举值 |

新任务沿用 `type: variant`，`variantOf: main`。校验改为恰有一个主任务、至少一个变式，主任务原 `variantTaskId` 仍指向首个推荐的合法变式。每个变式的 `variantOf` 指向主任务。原来的两任务课程照常加载。任务列表、主按钮和总结推荐使用任务标识和配置，覆盖现有 `main.js`、`views/course.js`、`workflows/course.js`、`views/summary.js` 以及结果动作中的固定 `variant` 路径。总结的 `variantCompleted` 等旧字段继续表达原近似变式，另增明确的迁移结果。同步给严格课程 Schema 补录当前内容已有的 `otherThemes`，用新旧两份实际课程包走一遍校验。

正方形的 `successCriteria` 使用现有比较器配置 `stage.x = 0`、`stage.y = 0`、`stage.heading = 0`、`stage.steps = 8` 和 `stage.moves = 4`。`square_single_repeat` 用 `program_roots(..., runnable_only=True)` 检查实际可执行结构。四次前进和四次转弯须来自同一个可执行循环。按任务要求，重复体由一块前进和一块转弯组成，先前进后转弯，重复 4 次，每次 2 步，转弯取 `90` 或 `270`。循环外可有不影响轨迹的动作，游离积木不计入。数值相同的数字积木参数和直接数字参数都通过 `number_input_value` 读取。手工拼出四组动作即使回到起点，也只显示「路线完成」并引导把两种动作放进同一个循环。

> 本期把正方形作为指定的循环练习。界面明确每条边的动作顺序和用块要求，验收按该要求判定。`270` 表示反方向转一个直角，儿童界面可称「向另一边转」。

## 4. 接口、快照与会话证据

### 4.1 归属规则

- 前端每次安装工作区时生成新的 `workspaceId`，包括切换任务、重来、装入作品和课程刷新。普通编辑、撤销和重做沿用它。继续复用 `pageVersion`、`programRevision` 和 `requestId` 判断异步结果能否应用。
- 后端用 `(courseId, contentVersion, taskId, workspaceId)` 定位本次练习。旧接口会话记录可以继续写入，增强教学判断只查当前范围。
- 对通过既有程序校验的 `program`，后端按 `target`、`courseRef`、`formatVersion` 和 `root` 或 `stacks` 计算 SHA-256。JSON 键排序，数组顺序保留，去掉 `metadata` 和 `stacks` 中纯布局的坐标，保留 `blockId`、连接、输入、游离组、执行顺序和 `legacy`。同一程序重新序列化时摘要稳定。前端现有的程序指纹继续用于界面判断，无需和后端哈希互通。
- 提示渲染、定位和回放前均检查所属页面、课程版本、工作区、程序修订号与目标运行。修改后可以显示旧结果的文字，并标记「上次运行」，旧定位和回放入口立即失效。切换任务和刷新课程时丢弃迟到响应。

### 4.2 API 增量

默认保留 `/api/v1`。各请求将范围放在 `learningContext.scope`，其中包含 `contentVersion`、`workspaceId`，并可包含 `courseId`、`taskId`。外层 `taskId` 继续使用原字段。新增对象限定字段和长度，标识沿用运行 ID 的字符规则，`program` 走原有结构、大小、嵌套与积木校验。请求内的 `courseRef` 须与本次 `CourseBundle` 一致。对象字段缺失时走原调用路径，提供了增强上下文但版本不符时返回可重试的课程刷新提示。

| 接口 | 新增请求 | 新增响应或作用 |
| --- | --- | --- |
| `POST /session/prediction` | 可选 `learningContext: scope + { program? }` | 返回 `predictionId`。有合法程序时记录程序摘要，没有时保留预测和运行门禁并记作未绑定预测 |
| `POST /runs` | 可选 `learningContext: scope + { predictionId?, seenHintIds?, workspaceSource? }` | 运行业务请求继续包含原 `program`。受理时固定课件、程序、预测关系和帮助状态。SSE `result` 新增可选 `learning` |
| `POST /tutor/hints` | 可选 `learningContext: scope + { program?, runRequestId?, seenHintIds? }` | 沿用原回复字段，增加可选 `learning`。用当前校验后的程序及同范围的运行证据决策。缺少合法程序时可给一般引导 |
| `GET /session/summary` | 沿用原请求 | 新增 `transfer`、`nextTaskId` 及可供界面渲染的本次观察，原字段继续可读 |

`seenHintIds` 由前端记录本工作区最近 8 个**已呈现**的 `answerLevel > 0` 回复的 `requestId`。本地预置、模型、局部示例一律采用这条规则。`self_try`、`skip`、迟到后被丢弃的回复和未呈现的回复均无计入。后端只接受当前范围中确实发出过的提示 ID，并去重；未知 ID 导致帮助状态无法确定。提示被呈现后孩子又修改积木，提示在本工作区仍计入帮助。可回放的针对性帮助只从正等级提示进入，并遵循同一记录规则。运行受理保存状态快照，终态重连或运行中后来收到的提示对该次结论无影响。

`workspaceSource` 取 `task` 或 `project`，由安装工作区时的来源映射。存在已验证的提示 ID 时记 `assisted`；只有来源是任务起始工作区且显式发送空数组，才记 `none`。来源为打开作品、字段缺失、提示 ID 无法核实且没有其他已验证 ID 时记 `unknown`。这些值描述本应用内的可观察帮助。

程序关联预测有三种状态。`exact` 要求预测 ID、范围及程序摘要全部匹配；`carried` 表示同一工作区有旧预测但程序不同或缺少摘要；`none` 表示无可用匹配记录。`exact` 才参与错因判断。`carried` 可在结果区展示「沿用上次猜想」，并推荐重新预测；原任务门禁和合法旧客户端仍然可以使用已有预测运行。无运行、未完成运行、目标未达成和证据不足分别表示。

### 4.3 建议的数据形状

以下片段展示「每次走 2 步，重复 2 次」的终态附加数据。`outcome` 取 `goal_met`、`goal_missed` 或 `run_incomplete`，`pattern` 记录本次观察，`traceQuality` 取 `verified`、`unavailable` 或 `inconsistent`，用于控制回放入口。缺失数值用 `null` 表示，无法验证轨迹时 `replay` 为 `null`，无法分轮时各动作的 `round` 为 `null`。

```json
{
  "learning": {
    "outcome": "goal_missed",
    "pattern": "loop_count_mismatch",
    "facts": {"targetSteps": 6, "actualSteps": 4, "moves": 2, "repeatTimes": 2, "stepsPerMove": 2},
    "predictionMatch": "exact",
    "traceQuality": "verified",
    "replay": {
      "rounds": 2,
      "actions": [
        {"round": 1, "blockId": "b-move", "kind": "motion.move", "steps": 2, "x": 2, "y": 0, "heading": 0, "moves": 1, "totalSteps": 2},
        {"round": 2, "blockId": "b-move", "kind": "motion.move", "steps": 2, "x": 4, "y": 0, "heading": 0, "moves": 2, "totalSteps": 4}
      ],
      "hasMore": false
    }
  }
}
```

辅导的 `learning` 包含 `pattern`、`runRequestId | null`、`anchorBlockId | null` 和 `nextAction`。`nextAction` 取 `predict`、`run`、`compare`、`locate_block`、`replay`、`edit_one`、`open_next_task` 或 `none`，前端映射到已注册的交互。绑定运行为空时禁止回放；定位只能使用通过校验的当前程序中的积木 ID。儿童界面用任务文案表达动作和事实。

正方形终态的 `learning` 另带 `routeMet` 和 `structureMet`，均为布尔值或 `null`。`routeMet` 由完成运行的舞台条件得出，`structureMet` 由程序条件得出。未知项用 `null`。`success` 仅在完整运行且两项均通过时为真。结构失败沿用 `failures` 回传可读文案。`learning` 由后端编排加到浏览器的 SSE 结果，worker 协议沿用现有字段。

总结新增 `transfer = { taskId, status, support, runRequestId }`。旧课程没有迁移题时返回 `transfer: null`。`status` 取 `not_started`、`in_progress`、`completed` 或 `skipped`，优先展示已完成的结果。`support` 取 `none`、`assisted` 或 `unknown`。同版本多次成功优先展示有证据的无提示课堂运行。仅 `completed` 且 `none` 时显示「这一次，在没有提示的情况下完成」。若同任务在本次会话的较早工作区曾使用提示，在观察中补充先前帮助记录。

### 4.4 存储、重试与故障

- 在 `SessionStore` 中增加有界的预测、提示、运行教学快照索引。建议每类最多保留 256 条新记录，终态按 `requestId` 去重，旧记录淘汰后使用缺证据路径。沿用现有通用证据上限 `MAX_EVIDENCE`。原始轨迹和完整程序仍按运行管理器已有的生命周期保留，教学索引只存必要事实、摘要与有限回放。
- `RunManager` 受理时捕获上下文，执行完成后先生成可选的 `learning`、保存摘要与尝试记录，再用现有单次终态发布逻辑发出 SSE。复用现有安全包装，索引失败时发布原运行结果并将教学数据省略。任何路径都要关闭运行槽；重连只能重放帧，不能再次追加尝试或证据。
- 会话内的写入和快照读取用现有锁，锁内只进行内存更新。线程等待、运行器和模型 I/O 放在锁外。课程热更新期间按受理时的版本写入，当前课程只消费自己的记录。
- 只有前后两次同范围完整运行，且定位积木 ID 相同、能确定一个数值或父连接发生变化时，生成 `edit_trace`。一轮改了多个位置、积木被删重建或上下文不完整时，可描述新观察并继续教学，不推断改动与成功的因果关系。

## 5. 错因判断和辅导策略

### 5.1 提取事实

建议在 `backend/tutor/evidence.py` 附近增加一个纯逻辑模块，输入为已校验的程序、捕获的课件、终态、预测关联；输出为受限的事实和建议锚点。遍历 `program_roots` 的可执行部分并跟随 `next` 与 `body`，以同一个 `blockId` 对齐结构和事件。结构证明「积木在哪里」，完成且校验过的事件证明「积木执行过」。运行结果回答「目标是否达成」。`status=completed` 与 `success=false` 组合表示程序完成但目标未达成。

| 优先级 | 事实与触发条件 | `pattern` | 孩子下一步 |
| --- | --- | --- | --- |
| 1 | 当前程序缺参数、校验失败或运行超时、取消、崩溃等 | `program_invalid` / `run_incomplete` | 采用已有错误提示、定位可确认的出错积木，或邀请再运行一次 |
| 2 | 没有匹配本轮的完整运行 | `not_run` | 有合法结构时可提示看看积木的位置，并邀请先猜再跑 |
| 3 | 正方形路线达标但结构检查未过 | `square_loop_structure` | 问「哪两个动作每一条边都会做？把它们放进同一个重复积木试试」 |
| 4 | 步数未到，唯一执行的前进在循环外，循环确实缺少前进 | `action_outside_loop` | 指向前进或循环，问「写在重复积木里面的动作有哪些？」 |
| 5 | 步数未到，唯一可解释的简单循环每轮走课程建议步数，但轮次偏少或偏多 | `loop_count_mismatch` | 前两轮回放后问「多走一轮会走到哪里？」或「少走一轮会怎样？」 |
| 6 | 步数未到，循环次数已等于目标步数除以建议步数，但每轮步长不同 | `move_steps_mismatch` | 指向那块前进，问「每一轮实际走了几步？」 |
| 7 | 预测与执行针对同一程序，预测值与实际移动次数不同 | `prediction_mismatch` | 显示预测与实际移动次数。若预测恰好等于总步数，再问「你刚才数的是动了几次，还是一共走了几步？」 |
| 8 | 目标已完成，预测没有明确冲突 | `goal_met` | 说出本次观察，建议进入下一题或总结 |
| 9 | 有结果但程序同时出现多个可能原因，或能够支持诊断的证据不完整 | `unknown` | 说出确定的结果，请孩子选一块观察或改一处再跑 |

表格按首个匹配项决定主提示。移动次数和步长同改、多组运动、嵌套循环或轨迹缺失时，可以报可验证事实，避免推测单一原因。两关的其他合法达标写法保留结果成功；没有观察到循环实际执行时，只总结步数目标达成。预测错配只是待确认的解释线索。

### 5.2 从错因选择帮助

| 时机 | 策略 | 等级 |
| --- | --- | --- |
| 第一次遇到本轮问题 | 一句具体提问或轻线索，给一个可操作动作 | 1 |
| 点击「再给一点提示」，或连续两次不同 `requestId` 的完整运行在同范围出现相同错因 | 用定位、回放或类比换一种呈现。有可靠回放时优先用于次数与步数问题 | 2 |
| 已经呈现第 2 级帮助且孩子再次要求更多 | 拆成小步骤或给不同数字的局部示例。当前关的完整程序需独立的示范入口 | 3 |
| 新运行中的错因改变，或提示对应的问题已解决 | 按新证据重新选择级别，先给较轻帮助或推荐下一题 | 1 |
| 选择「我自己试试」「先跳过」 | 允许回编辑或继续流程 | 0 |

同一运行反复普通点提示复用当前教学动作，普通点击只影响 UI，不构成重复失败。对连续运行的升级要求错因相同且中间没有其他结果。`example` 响应孩子的选择，给类比或同概念的非本题局部例子。新问题重新计算等级时，保留本工作区实际看过提示的事实，用于迁移总结。需要安全转回主题的输入本地处理，`skip` 继续复用已有反馈接口。

`engine.py` 决定 `action`、`answerLevel`、`pattern`、锚点和后续动作。`mock.py` 按动作、错因和等级选文案；缺精确模板时优先用相同动作的通用文案，再降级到明确可用的安全决策。模板只能填入决策提供的事实。更新 `tutor.replies.json`、`commonErrors` 与内容校验，至少覆盖表中的核心三类错因、无运行、未知和正方形结构错误。`answerLevel=3` 可用于局部示例；输出校验需将「教学帮助级别」与「是否揭示完整解答」分开处理。

## 6. 执行回放与界面

1. **提取片段。** 使用终态 `result.events`，在已校验的运行程序里查找 `blockId`。仅在完整运行中使用顺序严格递增、可配对的 `block_enter` / `block_exit` 提取实际执行的移动、转向。当前 `LineTracer` 会合并相邻同块行事件，事件数达到 `MAX_EVENTS` 或配对、块映射异常时降级。运行结果 `truncated` 主要表示输出截断，不能单独用于判定轨迹完整性。
2. **核对轨迹。** 使用已验证的参数和现有 `Stage` 运动语义重放观测到的移动和转向，逐动作生成坐标与步数，再与终态 `x/y/heading/moves/steps` 比对。运动数据相符时才提供回放。只有单个可识别循环且能按循环体动作顺序分组时才标轮次；其他可靠轨迹可按动作播。轨迹无法核对时使用普通运行结果和可确认的积木定位。
3. **限制呈现。** 在现有辅导区放「看看怎么走」，点击后从第一步开始，可上一步、下一步、结束。建议回放最多 12 个运动动作。步数题默认展示前两轮；正方形题展示完整路线，逐步播放四次前进与四次转向。窗口中止时保留可访问的文字，例如「第 2 轮，海龟累计走到 4 步」。截短的回放提示还有后续动作，独立显示终态结果。
4. **绘制路线。** `views/result.js` 按 `teaching.goalKind` 选择舞台呈现。`distance` 沿用原步数刻度；`square` 在现有舞台区域用小型 Canvas 绘制经核对的真实轨迹、起点、当前点与朝向，使用相同比例尺、等宽高的绘图区。目标轮廓可用虚线提示。移动却未转弯时显示实际直线路径。轨迹过长时标注可见片段，缺少可靠轨迹时显示可确认的位置、朝向和任务结果。正方形的结果摘要分别显示路线和循环结构的完成情况，兼顾键盘操作、文字可读和颜色区分。
5. **回到积木。** 复用现有定位回调、高亮和结果归属。`views/tutor.js` 用后端返回的 `anchorBlockId`，`views/runner.js` 把 `learning` 传给结果与场景。回放暂停状态由当前运行和工作区持有。编辑或替换工作区时关闭回放、高亮复位，提示建议重新预测和运行。前端发起的辅导请求只允许最新一条更新界面。

## 7. 可选模型接入

模型接入以本地规则和模板通过验收为前置。沿用 `CMK_TUTOR_MODE` 和现有环境配置、超时及兜底。新版在 `tutor_protocol.v1.json` 的模型请求定义中增加可选 `teachingDecision`，增强辅导请求使用该字段。部署时同步升级可选的模型适配端点；若旧端点拒绝扩展字段，已有本地回退负责继续课堂流程。新增端点集成测试覆盖这一情况。

- `teachingDecision` 传递动作、允许的帮助级别、错因枚举、允许引用的 `factIds` 和下一步意图。本地生成事实白名单，只含本次课堂的计数、目标、可定位积木类别和必要上下文。`blockId`、回放坐标与按钮由本地决定。
- 模型负责组织一句短提示或给已获准的类比。保留 `message` 和 `nextStep`，限制长度并对两者应用现有儿童安全、个人信息及完整解答校验。校验模型的 `action`、`answerLevel` 和可选 `factIdsUsed` 是否匹配决策，数值是否来自给定事实；结果数据或界面操作以本地字段为准。事实不足、直接索要答案、选择跳过或自己试时使用本地回复。
- 发送出站数据时使用字段白名单，只传课程文案与系统生成的简短事实。当前 `self_feedback` 的 `observedFact` 可能来自用户输入，需要排除；`programSummary` 改为本地生成的结构摘要，省略说话文本、原始问题、项目文件、stdout、完整程序和日志。脱敏诊断只记录失败类别、模式与关联请求 ID。
- 网络超时、协议不匹配、事实引用越界、越权给答案或输出校验失败时，退回与本地决策匹配的预置回复，保留「演示回复」标识。验收对比同一场景下模型和 mock 的教学动作、等级及证据引用，允许两种文案不同。

### 9.3 演示验收脚本

1. 用默认本地模式进入循环课程，跑完走四步。进入走六步，把循环设成 2 次、每次走 2 步。先猜动几次再运行，确认舞台显示「动了 2 次、走了 4 步」。
2. 点轻提示后再点「再给一点提示」。定位或回放指向当前循环，回放显示第 1 轮 2 步、第 2 轮 4 步。只把次数改成 3，确认旧回放已失效。重新预测并运行，得到 3 次、6 步。
3. 进入画正方形，使用「重复 4 次，前进 2 步，再转 90°」，预测前进次数后运行。舞台显示四条边和回到起点。打开总结，核对是否使用过提示、运行所属任务和下一步是否一致。
4. 用新的演示会话分别复验「直接拼四组动作」「看提示后通过」和「取消运行后继续」。在 Chrome 和 Edge 的 1280×720 与 1024×768 下检查回放入口、键盘焦点和文本反馈；模型端点断开时验证本地回退。

## 10. 发布与恢复

- 按任务顺序交付，先使用本地模式跑完固定课堂脚本。课程包与应用支持一起进入演示分支，发布前核对 `contentVersion`、课程加载、三份内容文件和任务工具箱。
- 如模型表现影响演示，恢复默认 `mock` 模式即可沿用已验收课堂流程。如需回退迁移题，用原版课程包恢复两关，并确认没有遗留 `nextTaskId` 或部分模板。若回退应用版本，使用与之匹配的课程包；新任务作品用支持该任务的应用打开。复验旧作品、预测门禁、跳过和终态恢复。
- Demo 观察项记录三类错因的命中、可靠回放生成、提示后复验和迁移完成时的帮助状态。用固定演示程序填写验收记录，避免把会话观察汇总成儿童能力等级。

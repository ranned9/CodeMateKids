# CodeMateKids 儿童编程工作台 UI/UX 综合开发方案

适用范围为 Windows Demo，面向小学三年级及以上儿童，以循环课「让角色走四步」和变式「小海龟走六步」为首轮实施样例。本文定义界面行为、模块改造、提交顺序、兼容策略和验收要求。第 2–8 节用于核对产品行为，第 9–12 节用于拆任务、实现、测试和发布。 [原改造建议](CodeMateKids_UI_UX_改造建议.md) · [项目架构](architecture.md)

## 1. 改造目标

孩子进入课堂后，能说出「我要让角色做到什么」，找到该操作的积木，提交预测、运行并解释结果。当实际表现与目标有差距时，孩子能从结果回到积木，改一次，再跑一次。

首个可交付版本以这条完整路径为范围。在两个目标窗口里同时交付当前任务、预测入口、积木编辑、舞台刻度、运行结果和重新运行。随后补齐错误定位、试错恢复、辅导和总结。样式变量随实际使用的组件建立，产品对标聚焦课程指引、编辑和反馈三个具体场景。

界面尺寸采用第 8 节的初始值。开发开始时采集旧版浏览器基线，首个版本按编辑任务实测校准断点。试用结果用于判断改造是否达到教学目标。

## 4. 页面结构与教学流程

### 4.1 页面分区

宽窗口同屏呈现任务、编辑、运行三个区域。编辑区包含工具箱和画布，画布使用剩余空间。窄窗口使用同一工作区，用短任务条和可切换的结果面板访问其他内容。

    宽窗口
    ┌───────────────────────────────────────────────────────┐
    │ CodeMateKids  循环课 · 当前任务         作品  帮助     │
    ├──────────────┬───────────────────────┬────────────────┤
    │ 当前任务      │ 工具箱 │ 积木画布      │ 运行 / 停止     │
    │ 目标与预测    │        │ 撤销 / 重做   │ 舞台与目标刻度  │
    │ 任务列表入口  │        │ 查看 Python   │ 结果与求助      │
    └──────────────┴───────────────────────┴────────────────┘

    窄窗口
    ┌───────────────────────────────────────────────────────┐
    │ 当前任务 · 走到第 6 格    任务详情     [当前主要操作]   │
    ├───────────────────────────────────────────────────────┤
    │ 工具箱和积木画布                        [结果] [求助]  │
    │ 从结果返回时恢复刚才的积木位置                         │
    └───────────────────────────────────────────────────────┘

| 区域 | 默认内容和交互 |
| --- | --- |
| 顶部 | 产品名、课程进度、作品菜单和保存状态。作品菜单提供保存和打开。帮助菜单提供操作说明、快捷键和系统信息 |
| 启动 | 准备期间显示简短状态。正常进入后折叠检查详情；如果仍需点击「进入课堂」，保留该按钮直至进入。环境阻塞或课程刷新待处理时，直接显示原因和恢复动作 |
| 任务 | 当前任务名、目标、简短完成条件和预测。其他任务、课程主题和长说明按需查看；任务切换沿用作品变更确认 |
| 工具箱 | 优先展示当前任务可用积木，类别较少时直接展示。保留点击添加和拖放入口。暂不可用的积木说明可按需查看 |
| 画布 | 保留标题、撤销、重做和定位入口。空工作区提示「点一下积木，或把它拖到这里」。有起始程序时就近引导第一次观察或修改。Python 预览标记为只读 |
| 舞台和反馈 | 运行或停止入口、角色和目标刻度、短结果、运行详情与求助。窄布局中使用同一套控制，在固定位置呈现主要操作 |
| 小结 | 完成了什么、本次观察到的一个具体行为、可以尝试的一个变式。达标后提供进入变式或小结的明确路径 |

### 4.2 主要操作随课堂状态变化

孩子可以先看或修改积木，也可以先猜。首次运行前需要有效预测，运行可用性继续由现有门禁决定。预测输入、运行和重新运行各在对应状态获得最高视觉优先级。

| 状态 | 默认动作与反馈 | 同时可用 |
| --- | --- | --- |
| 未提交预测 | 在预测问题旁突出「提交预测」 | 浏览、编辑积木与查看目标；Enter 可提交预测 |
| 已预测，程序还需调整 | 显示当前原因和能解决它的动作，如「去连接『当开始』」或「去填数字」 | 保留预测、继续编辑 |
| 可运行 | 突出「运行」 | 查看目标、修改积木、求助 |
| 正在运行 | 显示运行中，保持「停止」可找到；避免重复提交 | 查看实时反馈 |
| 正常结束，已达标 | 显示预测和目标对照，提供「试试变式」或「看小结」 | 返回编辑、查看本次运行 |
| 正常结束，未达标 | 显示实际差距，提供「回到积木」或可靠的定位动作 | 求助、修改、重跑 |
| 已停止或中断 | 提示本轮已停止或具体失败原因；终态确认后提供重试 | 断线期间继续使用原有停止与恢复机制 |
| 积木在上次运行后已修改 | 标明「上次运行 · 积木已修改」，突出「重新运行」 | 看上次结果，按需再猜 |

窄窗口跑完后，在稳定位置显示状态摘要和「查看结果」。若采用自动展开，前提是当前视图正等待本轮运行，且孩子能通过「回到积木」恢复视口和选中项。普通提示使用状态区，输入和拖放过程保持焦点。 [运行条件](../frontend/js/core/runGate.js) · [运行控制](../frontend/js/views/runner.js)

## 5. 舞台、结果和课程目标

### 5.1 舞台显示可比较的量

循环课采用带刻度的累计步数轨道。标出起点、当前累计步数和目标旗，首屏就能看到目标刻度。主任务目标为 4 步，变式为 6 步，视图从课程目标数据取得数值。角色和刻度使用同一比例。超过轨道范围时，用「已超过目标 N 步」或溢出标记表达实际差值。

轨道与辅助文字统一使用「累计步数」。后续课程若考察真实坐标、朝向或其他对象状态，按该任务的目标字段选择舞台表现。首版采用静态刻度和终态结果。若增加「慢一点看」或执行回放，先验证事件粒度、顺序和完整性，并提供减弱动态效果的呈现方式。 [舞台实现](../frontend/js/views/result.js)

### 5.2 结果首屏回答两个问题

以「小海龟走六步」为例，孩子猜 2 次，运行时角色动了 3 次，每次 2 步。

> 你猜它会动 **2 次**，实际动了 **3 次**。
>
> 目标是 **6 步**，小海龟走了 **6 步**，到达目标。

预测是否一致和任务是否达标分别用文字表达。任务正常完成但结果未达标时，显示目标差多少。运行停止、中断或缺少数据时，说明本轮可确认的观察。详细输出、朝向和执行信息按需展开。如果任务的主要观察对象是文字输出，摘要直接展示相关文字。

动作次数使用实际动作计数，累计步数使用步数字段。缺少动作计数的旧数据提示「这次没有记录动作次数」，照常显示可确认的步数。多轮对比保持相同单位。 [结果视图](../frontend/js/views/result.js) · [角色运行数据](../backend/runner/runtime_api.py)

### 5.3 结果跟随实际运行的程序

- 提交运行时，一并捕获程序副本及修订号、任务和作品上下文、预测值与请求标识。异步返回时沿用运行会话归属检查，从本次提交记录生成预测对照。
- 首版在当前任务和作品上下文中保留最近一次运行结果。修改、撤销或重做后按修订号标记「上次运行 · 积木已修改」。撤销后程序回到原样时，也可以提示重跑确认。
- 第一次预测可用于回顾。「再猜一次」提交成功后更新下一轮的值；提交期间显示保存状态，明确下一轮采用哪个值。沿用较早预测时显示「沿用上次预测」，点运行即可继续试。已经显示的运行结果继续引用当时的预测。
- 切换任务、打开作品或恢复初始积木时，沿用现有上下文切换与清理流程。晚到的运行、预测和辅导回复分别核对归属。

前端已有用于保存的程序修订号。配合运行会话和作品状态转换即可建立视图归属。 [状态装配](../frontend/js/main.js) · [运行会话](../frontend/js/core/runSession.js) · [作品与任务状态](../frontend/js/views/artifact.js)

### 5.4 对齐题意、完成标准和证据

主任务题意要求使用重复积木，当前成功条件只检查累计步数。变式的预期表现提到角色说话，成功条件只检查 6 步。首轮在课程文案中明确步数目标和循环练习要求，建议把「让它说一句话」写为变式的可选加练。 [课程内容](../content/demo-loop/course.json) · [现有目标判定](../backend/domain/program.py)

| 学习进展 | 可观察条件 | 反馈示例 |
| --- | --- | --- |
| 到达目标步数 | 本轮正常完成，累计步数等于当前任务目标 | 「走到第 4 格了」 |
| 观察到循环内的前进重复执行 | 本轮正常完成，且有可靠证据表明同一块位于循环体的前进积木被执行至少两次 | 「这块放在重复里的前进积木，至少执行了两次」 |
| 变式加练 | 角色实际说出一句话 | 「小海龟走到第 6 格，还说了『我走完啦』」 |

主任务允许「重复 4 次，每次 1 步」和「重复 2 次，每次 2 步」等解法。直接前进 4 步可以获得到达目标的反馈，再引导「试着把前进放进重复积木」。对同时使用循环与循环外移动的作品，分别说明累计步数与实际观察到的重复行为。游离的循环、零次执行的循环和只重复说话的循环均缺少循环重复移动的证据。

先交付准确的步数达标反馈和循环学习目标。循环证据不足时给出自查提示「再看看前进是否放在重复里」。下一阶段评估现有运行事件可否支持判定；若要调整证据契约或任务完成状态，独立实施并验证旧课程和旧作品。任务说明、完成条件、变式入口和总结用同一口径。

## 6. 让失败可定位，试错可恢复

| 场景 | 儿童看到的反馈与动作 | 实现约束 |
| --- | --- | --- |
| 改数字、插入后想反悔 | 画布旁可直接找到撤销和重做 | 复用编辑器历史，保持结构和参数修改的撤销粒度 |
| 合法拖放 | 插入线或槽轮廓显示可放位置，必要时预览结构 | 拖放预览和实际提交共用目标解析 |
| 拖到非法位置 | 「这里放数字」「这个动作可以放到重复里面」等明确反馈 | 颜色结合形状或文字，取消或失败时恢复完整结构 |
| 删除完成 | 简短提示「积木已删除」，提供「撤销删除」 | 入口须指向这次删除，后续编辑改变撤销栈后及时失效 |
| 程序有明确问题 | 「这里缺一个数字」或「把前进接在『当开始』下面」，提供「定位积木」 | 使用本地校验或运行返回的有效积木 ID；目标不明确时给检查方向 |
| 程序正常结束但未达标 | 「目标 6 步，这次走了 4 步」，提供「回到积木」或「给我一点提示」 | 先说可观察的差距；有明确依据再定位积木 |
| 恢复初始程序 | 次级菜单提供「恢复本题初始积木」，说明影响范围 | 沿用未保存修改确认和课堂重置流程 |
| 窄布局回到画布 | 回到离开时的滚动位置和选中积木；从「定位积木」进入时显示目标积木 | 目标已删除时，焦点回到画布工具栏或可用的画布节点 |

数字槽保留直接输入和加减按钮，错误在槽附近或画布状态区说明。作品菜单显示「有未保存修改」等状态。异步保存完成时按被保存的版本更新；孩子继续修改后，仍应看见新修改未保存的提示。 [画布](../frontend/js/views/canvas.js) · [拖放](../frontend/js/editor/dnd.js) · [作品工作流](../frontend/js/workflows/projects.js)

## 7. 辅导与会话小结

### 7.1 辅导先给下一步

| 时机 | 默认内容和入口 |
| --- | --- |
| 初次求助 | 「给我一点提示」放在结果旁，也可从编辑区帮助入口打开 |
| 收到轻提示 | 展示一条短建议，优先提供「我再试试」；有可靠位置时附「看看这块积木」 |
| 主动请求更多帮助 | 按已有分层提供「再给一点提示」「换个例子」或「分步骤讲解」 |
| 主动自由提问 | 按需展开输入区；输入时保证文字编辑按键正常工作 |
| 辅导暂时不可用 | 简短说明当前状态，提供「重试」和「继续练习」；运行仍可按原有条件进行 |

先给动作，再给一句理由。例如「数数小海龟一共动了几次，再看看重复积木里的数字」。模式、证据和详细解释放在详情，演示回复身份可查。完整解法沿用课程与辅导门槛。

提示请求记录当时的任务、程序修订号和用到的运行结果。孩子等待时若修改程序，旧回复标记「根据上次积木给的提示」，定位前检查目标积木是否仍在且仍适用。切换任务或作品后的旧回复按上下文丢弃。定位目标使用已校验的本地数据或明确的协议字段。 [辅导视图](../frontend/js/views/tutor.js) · [异步归属](../frontend/js/core/viewContext.js)

### 7.2 小结用观察事实引向变式

先说这次完成了什么，再举一个本次观察到的操作或结果，最后给一个可尝试的小挑战。例如「你把每次走 1 步改成了 2 步，看到角色每动一次会走得更远」。只有存在对应修改和运行证据时才使用这句。用过的提示、跳过的任务和还需观察的内容放入可展开详情。小结注明「仅代表本次会话观察」。 [小结视图](../frontend/js/views/summary.js)

## 8. 窗口、视觉和辅助操作

### 8.1 布局以画布能完成任务为准

| 场景 | 推荐布局 | 需要验证 |
| --- | --- | --- |
| 宽且高度充足 | 初始采用宽度 ≥1366 CSS px 且高度 ≥760 CSS px 时显示三栏；画布分配剩余空间 | 目标、主要积木与舞台同屏，较长反馈可滚动 |
| 1280×720 低高度窗口 | 使用短任务条或较窄任务区；运行面板按实测决定同屏或切换；进入课堂后收起启动详情 | 展开工具箱、修改数字、运行与停止都可完成，结果可返回编辑 |
| 1024×768 | 短任务条加主画布，任务详情和运行结果按需展开 | 核心流程完整，主操作可达，页面无横向溢出 |
| 高倍缩放或更窄窗口 | 简化布局保留当前目标、编辑、运行和结果；极窄时提供放大窗口的提示 | 正文字号和主要控件可读可用，键盘可进出面板 |

主区使用 CSS Grid 或 Flex，画布列采用 `minmax(0, 1fr)`，嵌套滚动容器明确可缩小的边界。宽屏从顶部约 56px、任务栏 220px、工具箱 160px、反馈栏 260px、区间距 12px 起步。临界视口下若画布无法顺畅完成嵌套和数字槽操作，提前进入紧凑布局，再用相同程序复验。

折叠系统状态、代码预览和详细输出后，优先把节省的高度给画布。明确画布、工具箱和侧区的滚动边界。小高度布局允许内容按需滚动；浏览器缩放按实际 CSS 视口触发布局。Canvas 尺寸、DPR、逻辑坐标、指针命中和数字输入层需同步，面板切换后检查画布原有最小尺寸假设。 [样式](../frontend/css/app.css) · [尺寸和坐标换算](../frontend/js/views/canvas.js)

### 8.2 统一视觉和操作反馈

- 以 4px 为基础间距，从 8、12、16、24px 选择常用值。中文正文从 14–16px 起步，目标和关键数字使用更明显的字号或字重；主要按键高度从 40–44px 起步，用真实窗口验证。
- 通过现有 CSS 变量统一字体、间距、圆角与状态色。主色用于主要操作，成功、警告和错误同时带文字或图形。边框与阴影用于区分区域、菜单等界面层次。
- 优先统一实际使用的组件，包括顶部栏、任务卡、工具箱项、画布工具栏、运行结果、辅导卡片、对话框和提示条。按钮定义正常、悬停、聚焦、按下、禁用和进行中反馈；禁用态对应明确原因。
- 主要图标配动作文字，例如「运行」「撤销」「打开作品」。提示可通过键盘和点击访问。放置合法性、错误位置和结果结论使用颜色之外的文字或形状。
- 保留清晰的 `:focus-visible`，用现有语义镜像聚焦、选择和操作积木。抽屉关闭后焦点返回触发按钮或目标积木；普通提示通过状态区播报。
- 键盘验收覆盖添加积木、修改数字、删除、撤销、运行、求助和退出面板。任意嵌套位置的精确键盘选择可另行完善，与指针路径共用目标解析。快捷键与输入框、按钮、菜单和对话框的正常按键兼容。
- 状态过渡尊重 `prefers-reduced-motion`。运行高亮保留可感知的非颜色变化，动画结束后结果仍可阅读。

### 9.2 状态归属与更新契约

```ts
type RunViewContext = {
  requestId: string;
  taskId: string;
  pageVersion: number;
  programRevision: number;
  predictionValue: number | null;
```

### 9.3 预测、运行和结果的实现顺序

1. **提交预测。** 按钮和 Enter 走同一个提交入口。输入按整数 0–1000 校验，0 是有效值。请求发出后暂时锁住重复提交，同时保留用户刚输入的内容。仍在同一课程版本的成功响应可以更新该任务的预测记录，只有任务和页面版本仍匹配时才更新当前表单。失败时在输入旁提供重试，保留先前已确认的预测。较早程序版本的已确认预测显示为沿用。载入新内容版本时清空本地已确认预测，旧版本的迟到响应直接丢弃。
2. **展示主要操作。** 启动阻塞或只读作品优先呈现对应原因；运行中展示本轮状态和停止；其次展示预测、程序校验动作、运行或重新运行。若阻塞原因需要带到积木，给 `evaluateRunGate()` 增加可选结构化字段，如 `reasonCode` 和 `blockId`，保留已有 `allowed` 和 `reason`。运行入口继续执行同一门禁。
3. **提交运行。** 沿用 `tryBegin()` 防重入。构造请求和本地快照后切换提交状态，沿用取消凭据、SSE 订阅、`pageVersion` 和当前请求检查。运行中前往其他面板时维持会话；切换任务、作品和重置沿用离开流程。
4. **响应终态。** 结果与运行来源成对更新，结果渲染器从快照取预测，使用返回的 `objects` 获取角色状态。提交被拒时显示本次提交失败及恢复动作，已存在的上次结果仍可查看。SSE 断开后用摘要确认运行终态，缺少角色详情时展示该轮状态和重试入口。收到完整结果时才显示本轮次数和步数。
5. **编辑后刷新。** 把 `handleStateChange("program")` 中直接隐藏对照的逻辑改为更新旧结果标记。重新运行以同一按钮发起，完成后替换最近结果；选中积木、折叠详情、打开 Python 预览等纯展示动作无需重跑。
6. **完成后导航。** 变式完成时显示「看小结」，把当前自动打开小结的路径改为由孩子触发。所有进入变式和其他任务的入口复用同一个任务切换流程，统一检查任务可进入状态、未保存修改和离开运行会话。

### 9.5 画布定位与面板实现

- **定位积木。** 在 `EditorView` 上补充从积木 ID 定位到可见画布范围的入口。用布局节点矩形计算需要的横纵向滚动值，按内容范围钳制，更新选中并刷新画布。键盘触发时同步语义镜像焦点。ID 不存在或不属于当前作品时，给出通用检查提示和回到画布的入口。
- **窄窗口。** 结果、任务详情和辅导按需展开在各自区域。用按钮绑定 `aria-expanded` 与可见区的 `aria-controls`；关闭后还原触发点。结果内容需要更多空间时允许正文滚动，运行与停止控件不遮挡画布的编辑热区。
- **尺寸变化。** 继续利用 `ResizeObserver`，由 CSS 可用宽高驱动画布与数字控件重算。校准 Canvas 后备缓冲尺寸、设备像素比、工作区滚动边界和 `pointFromEvent()`。断点切换改变命中几何时，通过现有拖放取消路径结束未提交的拖放。画布重新可见时以当前容器尺寸刷新。
- **撤销删除。** 复用 `History` 中已有的删除事务。提示出现时保存本次页面版本和事务标识或栈顶引用，执行前确认关联仍有效。后续历史变动、任务切换或提示到期后收起。界面通过 `canUndo()`、`canRedo()` 得到按钮状态。
- **键盘。** 调整现有 document 级快捷键的处理条件。焦点处于原生按钮、表单、链接或面板控件时，由对应控件处理 Enter、方向键与 Escape；在积木工作区内才处理选中积木的编辑、删除和镜像导航。运行和求助用可到达的按钮作为鼠标和键盘统一入口。

### 9.6 课程判定和辅导的落地方案

1. 从当前任务的 `successCriteria` 查找 `stage.steps` 的有效等值目标。目标缺失、含多个不同值或条件类型不适用于跑道时，使用普通舞台和任务描述。阶段一使用后端的 `success` 表达整体达标，运行结果的实际步数字段用于说明差距。
2. 阶段三先调整主任务的循环措辞、变式的可选说话任务和对应提示，更新内容版本，并验证已保存作品仍匹配课程。从同一来源提取目标数字，避免在布局、结果文案和课程里分别写 4、6。
3. 循环证据先复用真实终态的事件。按提交的程序建立可执行积木索引，进入循环节点的 `body` 时记录所属循环，处理该循环节点的 `next` 时回到外层。终态为 `completed` 时，按事件序号去重，同一块位于循环体的 `motion.move` 至少有两次可配对的进入和退出事件，才展示「这块在重复里的前进积木至少执行了两次」。事件按行映射聚合且有上限，证据缺失时使用自查提示。在真实 Worker 上校验直接前进、两个正常解法、内外混合、游离循环和事件不完整的分支。 [事件来源](../backend/runner/worker.py) · [终态发布](../backend/service/run.py)
4. 以上循环消息作为观察反馈。若后续需要把它变成后端完成条件或持久教学证据，再单独定义事件充分性与协议发布方式。阶段三需要展示的本次课堂小结，使用后端当前任务完成与运行事实，或有足够证据的本轮观察；文案注明来源和本次会话范围。
5. 辅导定位优先取既有错误对象中的有效 `blockId`，或由稳定的本地规则从当前积木树找出唯一匹配目标。模型文本作为教学建议显示。请求等待中修改积木时按第 9.2 节处理，并在应用定位动作之前重新验证目标。

### 11.2 核心用例

| 用例 | 操作 | 通过条件 |
| --- | --- | --- |
| 启动与恢复 | 分别在课堂就绪、环境受限和课程刷新待处理时打开页面 | 就绪后可顺利进入，受限时能看见原因和重新检查入口，刷新取消后当前课堂可继续使用 |
| 首次运行 | 进入主任务，给出预测，运行起始程序 | 能找到当前目标和唯一主要动作；结果同时说明预测对照与目标差距 |
| 连续试跑 | 改一个数字后重跑，分别覆盖沿用预测、再猜一次和预测提交失败 | 编辑后显示旧结果标记；运行结果使用提交时的版本；失败的预测更新可重试，既有结果保留 |
| 次数与步数 | 变式每次走 2 步，重复 3 次；提交一个与实际不一致的预测 | 明确「动了 3 次」「走了 6 步」「到达目标」 |
| 步数目标和循环 | 分别试直接前进、4 次乘 1 步、2 次乘 2 步及游离循环 | 步数结论来自运行；循环反馈基于可靠证据；两类循环解法均可达标 |
| 错误定位 | 数字槽留空或触发已有定位信息的错误，点「定位积木」 | 指向正确目标；无有效目标时给可执行的检查方向 |
| 编辑恢复 | 合法嵌套，尝试非法放置，删除后撤销 | 提示与实际落点一致；失败后结构完整，撤销后积木和参数恢复 |
| 尺寸与焦点 | 缩放和滚动后拖放；侧栏开合后再编辑数字 | 指针、预览、结构落点与输入控件对齐；Tab 可到达可见焦点 |
| 停止与断线 | 运行中停止，验证断线恢复路径 | 状态明确，确认旧运行终态后可再跑，旧事件归属正确 |
| 保存与切换 | 保存时继续编辑，切换任务，打开旧版作品 | 保存状态对应正确版本；未保存修改收到提示；旧作品可加载并运行适用任务 |
| 辅导与小结 | 请求提示后修改程序或切换任务，完成变式后看小结 | 提示版本可辨识，无跨任务串扰；小结引用已有事实 |

### 11.3 性能和试用

- 运行现有 Python 测试和前端 Node 检查。拖放吸附、撤销和重做沿用现有 P95 ≤100ms 的目标，各记录至少 20 次。记录设备、浏览器、程序规模与采样口径，从动作发生量到可见反馈，保留实测结果。 [运行与回归命令](run.md) · [既有验收记录](acceptance.md)
- 用「小海龟走六步」做一次没有口头操作提示的试用。观察孩子能否找到目标和第一次运行入口，能否说清动了几次、走了几步和下一步想改什么，以及是否能独立启动第二次运行。匿名记录成人介入、停顿位置、误操作与恢复用时。
- 对比改造前后的同一场景，优先看首次与第二次运行是否完成、是否能解释结果、是否需要成人帮助。用小规模试用发现问题并安排后续优先级。

## 12. 发布、风险和回滚

### 12.1 合并与交付条件

1. D04 达标后提供首轮可演示版本，附 1280×720 与 1024×768 的实际截图和核心路径结果。
2. D07 完成后更新运行说明的当前课程内容版本、验收记录和已知限制。交付说明列出已验证浏览器、缩放组合、课程内容版本和对应提交。
3. 将运行失效、重复提交、数据错配、作品丢失、焦点陷入、拖放命中错误和核心流程被裁切列为阻塞问题。浏览器和脚本回归均通过后再合并最终版本。试用暂未安排时，记录待验证的体验目标。

### 12.2 主要风险与处理

| 风险 | 观察信号 | 处理 | 相关任务 |
| --- | --- | --- | --- |
| 布局压缩导致积木和数字控件错位 | 指针落在插入线外，数字按钮盖住积木，窄屏只能看到部分循环 | 对齐容器、画布缓冲和逻辑尺寸；调整断点；两种缩放重复验证 | D02、D04、D07 |
| 运行、预测和辅导响应串到新页面 | 切换后出现上一题的角色、预测或提示 | 请求前捕获上下文；应用成功和错误响应前检查归属；用延迟和乱序响应复验 | D03、D05 |
| 任务切换绕开未保存确认 | 从小结直接进入变式时丢失新修改 | 所有任务入口共用切换路径；覆盖取消保存与保存失败 | D03、D05 |
| 运行事件不足以证明循环行为 | 普通前进或游离循环被说成用了循环，或事件被截断 | 按完整终态和可验证事件给观察反馈；证据不足时提示自查 | D06 |

| 界面更新影响高频编辑 | 拖动间歇卡顿、弹层抢走输入焦点 | 缩小重绘范围；复用画布刷新和暂存输入；对比旧版的 P95 与焦点路径 | D05、D07 |

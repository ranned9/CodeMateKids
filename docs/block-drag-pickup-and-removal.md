# 积木拿起与收回开发文档

## 交互目标

工具箱继续展示小尺寸积木。按住积木后，指针下的积木平滑放大到画布上的尺寸，拖过工具箱和画布边界时保持可见。将画布里的积木拖回工具箱，松手后从释放点缩小并淡出。拖放结果继续由画布的连接规则决定。

## 操作行为

| 操作 | 反馈与结果 |
| --- | --- |
| 按住工具箱里的积木 | 在缩略图原位显示拖动浮层，约 150 毫秒放大到画布尺寸。浮层始终以按下的位置为抓取点，缩略图保留原来的占位。 |
| 拖过工具箱与画布之间的空隙 | 浮层继续跟随鼠标、手指或触笔。进入画布后按现有规则显示插入线、可放置轮廓或非法原因。 |
| 在可连接的位置松手 | 重新检查落点，成功后吸附到插入线对应的位置。同一帧用画布积木替换浮层。 |
| 在允许自由放置的画布空白处松手 | 按现有自由放置规则落下，积木保持抓取点与释放点的相对位置。 |
| 把画布里的积木拖入工具箱 | 保持画布尺寸，沿用工具箱红框和「松手移除积木」提示。松手前拖出工具箱，清除移除提示并继续拖动。 |
| 在工具箱内松手 | 按当前移除规则提交一次删除。成功后，实际被删除的积木在释放点用约 180 毫秒缩小并淡出。可以通过「撤销」恢复。 |
| 在无效位置松手或取消手势 | 清除浮层和落点提示。画布上的原积木恢复显示，工具箱来源的积木不添加到程序。 |
| 点击或通过键盘添加 | 短按未越过现有拖动阈值时，沿用点击添加。`Enter` 和空格继续一次添加一个积木。 |

拖入工具箱的删除范围与现有规则一致。容器积木与其中的动作一起移除，链上后续积木继续留在画布。拖动可以带起一组积木，进入移除区时只预览将被移除的部分，避免把仍会保留的后续积木一起缩小。

## 前端实现

| 位置 | 修改内容 |
| --- | --- |
| [toolbox.js](../frontend/js/views/toolbox.js) | 从实际的缩略图画面读取尺寸和按下位置。点击、键盘添加和积木筛选继续走现有入口。 |
| [dnd.js](../frontend/js/editor/dnd.js) | 在 `begin()` 建立浮层。`onMove()` 更新指针位置和命中反馈，`onUp()` 以松手时的坐标提交。由 `teardown()` 统一清理。 |
| [render.js](../frontend/js/editor/render.js) | 复用 Canvas 积木画法生成浮层图像。将浮层中的积木外观与画布内的连接提示分开绘制。 |
| [canvas.js](../frontend/js/views/canvas.js) | 用 `pointFromEvent()` 将指针转换为画布局部坐标。继续通过 `commitDrop()`、`deleteBlock()` 更新程序树和撤销记录。 |
| [app.css](../frontend/css/app.css) | 定义固定在视口的浮层、抓取阴影、缩放和淡出。沿用已有移除提示，并适配 `prefers-reduced-motion`。 |

### 浮层与坐标

- 将浮层挂到 `document.body`，使用 `position: fixed` 和 `pointer-events: none`。这样跨出带 `overflow: hidden` 的画布或可滚动工具箱时仍能显示，`elementFromPoint()` 也能命中下方的真实工具箱。
- 放大前以缩略图实际绘制边界为准，放大后以画布布局的当前积木宽度和显示比例为准。计算宽高时使用 CSS 像素，Canvas 的设备像素比只用于清晰度。容器和嵌套动作沿用已有布局与绘制顺序。
- 记录抓取点在积木里的相对位置。每帧按 `浮层左上角 = 指针坐标 − 抓取点相对位置 × 当前显示尺寸` 放置浮层。自由落点使用同一个抓取偏移经 `pointFromEvent()` 换算，替代工具箱拖动时的固定偏移。
- 当画布来源的移动越过阈值时，隐藏原位上正在拖动的绘制层和相应的数字输入浮层，继续保留布局数据供命中检测使用。取消时恢复绘制。鼠标移动优先更新浮层位置，绘制刷新可合并到 `requestAnimationFrame`。

### 提交与清理

1. `pointerdown` 可以立即开始拿起动画，当前 6 像素移动阈值继续用于区分点击和拖放。鼠标点击参数区时沿用参数编辑；次要指针忽略。按住但没有拖动时，松手按原有点击规则处理。
2. 拖动阶段持续解析最新的 `targetId`，保持现有端口与分支相邻校验。画布只画连接线、目标框和状态文字，浮层负责显示跟手的积木。移除区域仍使用指针实际位置命中，便于在指针捕获期间正确判断。
3. `pointerup` 先复核任务仍可编辑，再重算落点并立即提交。删除成功才播放缩小动画。动画使用删除前的图像快照，动画完成事件只负责清理浮层。删除、撤销和自动保存的进度独立于动画。
4. `pointercancel`、`lostpointercapture`、窗口失焦、切换任务或开始运行时，按现有取消路径释放指针捕获并清除浮层、插入线和移除提示。新手势开始时清理上一轮收回动画的残留。系统开启减少动态效果时，立即切换尺寸和移除浮层，保留落点提示与撤销入口。

## 开发顺序

1. 从现有 Canvas 绘制提取拖动图像，接好工具箱按住放大和跨区域跟随。
2. 将画布预览收敛到连接提示，接入工具箱移除命中和删除后缩小动画。
3. 打通取消清理和撤销，校对不同缩放、滚动位置及鼠标、触屏和键盘操作。

## 验收清单

| 场景 | 通过标准 |
| --- | --- |
| 从缩略图拿起 | 从中央和边缘按住都能平滑放大。抓取点保持稳定，工具箱列表不抖动。 |
| 跨区域放置 | 跨越工具箱和画布时浮层连续可见。在空画布、普通连接处、循环或分支内部都能按提示放置。 |
| 收回与撤销 | 进入工具箱时出现移除提示，离开时消失。松手仅删除一次，缩小画面与删除范围一致，一次撤销恢复原结构和位置。 |
| 快速松手与非法目标 | 拿起动画未结束也能准确放置。无效放置和取消后，程序树、撤销栈和本地草稿没有新修改。 |
| 连续操作与兼容性 | 连续拖放、急速反向拖动、缩放和滚动时没有重复积木或残留浮层。短按添加、键盘添加、编辑参数和减少动态效果均可用。 |

自动化回归扩展 [js_editor_check.mjs](../tests/js_editor_check.mjs) 中已有的拖放用例，覆盖单次提交、取消清理和快速松手。浏览器手工验收检查放大手感、抓取点稳定性和工具箱边界处的视觉衔接。

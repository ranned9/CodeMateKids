# CodeMateKids 网页模型接入与教学 Agent 开发文档

本方案面向 CodeMateKids 的 Windows 单机 Demo。第一阶段让操作者在网页填写模型 API 配置，用虚构题目测试真实连接，启用后在课堂收到基于本轮事实的模型回复。第二阶段让小老师在同一道题里追问、记住孩子的回答，并据此选择定位积木或回放等教学动作。

| 项目 | 基线与范围 |
| --- | --- |
| 开发基线 | 循环课程 `1.3.0`，FastAPI 同源服务，原生 JavaScript 工作台，Python 3.12 运行器 |
| 网页入口 | 「系统信息」中的「模型接入」，面向管理 Demo 的操作者 |
| 第一阶段 | 网页配置、真实接口测试、启用和停用、真实辅导回复、本地回退 |
| 第二阶段 | 同一题内的多轮对话、模型选择教学动作、后端核对事实与动作、前端确认并呈现 |
| 配置存续 | 网页配置和课堂对话仅保存在本机服务进程内。浏览器刷新后可读当前状态，服务重启后按启动配置初始化 |
| 验证数据 | 使用虚构题目、虚构回答和本地 Demo 运行事实 |

## 2. 网页模型配置

### 2.1 页面与交互

在 `frontend/index.html` 的「系统信息」区域增加独立的「模型接入」表单，作为 `system-info-body` 的同级元素。现有系统信息刷新时可重绘自己的内容，模型表单由独立的视图函数管理。配置表单按键盘顺序组织，测试和启用结果通过页内状态文本反馈。

| 控件 | 行为 |
| --- | --- |
| API 基础地址 | 填写模型厂商给出的 API 基础地址，例如 `https://api.openai.com/v1`。字段下方显示该适配器使用的路径格式 |
| 模型名 | 填写厂商提供的完整模型标识。按原值提交，只去除首尾空白 |
| API 密钥 | 使用密码输入框。测试请求提交后清空，当前状态只显示「已配置」或「未配置」 |
| 测试连接 | 使用固定的虚构循环题发起一次请求。通过后显示模型名、耗时及可启用状态，失败时显示可重试原因 |
| 启用模型 | 仅提交本次测试的凭据标识和配置版本。成功后下一次符合条件的课堂求助使用该配置 |
| 使用演示回复 | 切回 `mock` 并清除网页提供的活动密钥和待启用配置 |

页面打开时先读取当前配置。正在使用模型时，编辑表单、测试其他配置或测试失败都不改变当前课堂。地址、模型名或密钥在测试通过后再次编辑时，页面清除本轮的「可启用」状态。测试中禁用重复点击，用户仍可返回课堂。输入草稿、请求和测试结果跟随表单版本，旧响应只允许更新它所属的表单。

当前配置区使用「演示模式」「真实模型已启用」等状态文案。每条课堂回复独立显示「真实模型」或「演示回复」。真实模型临时失败时保留选用配置，当前回复显示本地回退原因，后续合适的求助仍可发起真实请求。启动时的系统检查只报告配置是否启用，连接能力由测试接口确认。

### 2.2 服务端配置状态

在 `create_app` 中为每个 FastAPI 实例创建一份进程内配置管理器。保留不可变的启动 `Settings`，按请求取得运行时配置快照，快照包含 `revision`、配置来源、适配器类型、模型名、地址及密钥引用。对外状态由专门的 DTO 投影。修改状态用锁，锁外执行网络请求。

| 状态来源 | 生效条件与生命周期 |
| --- | --- |
| `default` | 以默认设置启动。当前模式为 `mock` |
| `environment` | 原有 `CMK_TUTOR_MODE=model`、端点和密钥齐全时，服务启动后按旧辅导协议生效。读取网页状态时只报告配置来源及密钥是否存在 |
| `web` | 测试通过并由操作者点击启用后生效。启用网页配置前保持原来源生效 |
| `web` 且 `mock` | 点击「使用演示回复」后，本次进程进入演示模式并清除网页提供的密钥。重启时再次读取启动配置 |

`revision` 从 `0` 起，每次启用或停用成功后递增。待启用的测试结果使用随机 `testId`，有效期 10 分钟，进程内只保留一份。对外用 UTC 时间表示 `expiresAt`，内部用单调时钟判断过期。发起新测试时使上一个待启用结果失效。测试完成时校对发起时的配置版本和测试顺序，只有最新测试可以置为待启用。测试失败或候选过期时，释放候选密钥及状态。启用时在同一把锁内校对版本、检查有效期、消费 `testId` 并切换配置，避免多标签页覆盖彼此的修改。

## 3. 模型配置 HTTP 接口

现有接口使用 `{ "ok": true, "data": ... }` 或 `{ "ok": false, "error": ... }` 包封，新接口沿用该格式。路径统一挂在 `/api/v1/tutor/model-config`。请求 DTO 严格校验字段，限制 `baseUrl` 512 字符、`model` 160 字符、`apiKey` 2048 字符。应用配置状态以 `Cache-Control: no-store` 返回。

| 方法与路径 | 请求 | 成功结果 |
| --- | --- | --- |
| `GET /api/v1/tutor/model-config` | 无 | 当前模式、配置来源、配置版本、公开配置字段及 `apiKeyConfigured` |
| `POST /api/v1/tutor/model-config/test` | `expectedRevision`、`baseUrl`、`model`、`apiKey` | `testId`、`revision`、`model`、`latencyMs`、`expiresAt`。当前课堂继续使用原配置 |
| `POST /api/v1/tutor/model-config/activate` | `expectedRevision`、`testId` | 启用后的配置状态 |
| `POST /api/v1/tutor/model-config/disable` | `expectedRevision` | 演示模式状态。清理网页配置和当前待启用测试结果 |

### 3.1 配置状态和请求示例

以下是启用成功后的 `data`。使用默认演示模式或旧环境变量网关时，公开的 `baseUrl` 和 `model` 可为 `null`。`effectiveMode` 只取 `mock` 或 `model`。

```json
{
  "effectiveMode": "model",
  "source": "web",
  "revision": 2,
  "baseUrl": "https://provider.example/v1",
  "model": "example-model",
  "apiKeyConfigured": true
}
```

测试请求使用以下字段。示例是占位值，实际密钥仅在操作者的网页输入时提交给本机服务。启用请求只使用测试结果给出的 `testId` 和 `revision`。

```json
{
  "expectedRevision": 1,
  "baseUrl": "https://provider.example/v1",
  "model": "example-model",
  "apiKey": "<operator-supplied-key>"
}
```

### 3.2 错误与恢复

| 场景 | 建议错误码或分类 | 前端行为 |
| --- | --- | --- |
| 配置字段缺失、地址不符合格式 | `MODEL_CONFIG_INVALID`（422） | 提示修改对应字段，保留地址与模型名 |
| 来源或目标地址被拒绝 | `MODEL_CONFIG_FORBIDDEN`（403） | 显示「这个地址无法用于模型测试」或「请从本机打开设置」 |
| 配置已由其他标签页改变 | `MODEL_CONFIG_CONFLICT`（409） | 刷新当前配置，按新版本重新测试 |
| 测试标识过期、被替换或已启用 | `MODEL_TEST_EXPIRED`（409） | 清除启用状态，提示重新测试 |
| 上游鉴权失败、模型地址不可用、限流 | `MODEL_TEST_FAILED`（502）及 `auth`、`endpoint`、`rate_limit` 类别 | 提示核对密钥权限、地址或模型名，限流时稍后再试 |
| 网络超时、上游拒答、截断或输出校验失败 | `MODEL_TEST_FAILED`（502）及 `timeout`、`refusal`、`invalid_response` 类别 | 报告本次测试结果，继续使用已生效的课堂配置 |

分类由后端映射为固定短文案。上游响应正文和异常原文留在解析边界，返回给页面的错误字段只包含已知类别。一次临时故障只影响本次请求。课堂回退沿用 `fallbackReason`，浏览器用自己的文案映射，配置测试由本机错误包封直接报告。

## 4. 模型适配与第一阶段课堂调用

### 4.1 API 兼容范围

第一阶段采用 OpenAI 风格的 Chat Completions 请求形状作为网页适配协议。服务商和模型由操作者选择，所选端点需接受该形状和 JSON 模式。浏览器填写带 API 前缀的 `baseUrl`，例如 `/v1`，后端移除末尾斜杠再拼接 `/chat/completions`，并在服务端添加 Bearer 鉴权。适配器从 `choices[0].message.content` 读取 JSON 文本。连接测试同时验证网络、模型和输出契约。 [Chat Completions 官方接口](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create) · [JSON 模式官方说明](https://developers.openai.com/api/docs/guides/structured-outputs#json-mode)

```json
{
  "model": "example-model",
  "messages": [
    {"role": "system", "content": "你是少儿编程老师。只输出含 message、nextStep、uncertainty、factIdsUsed 的 JSON 对象。给一句短提示，引用数值时使用给定的事实占位符。"},
    {"role": "user", "content": "目标为 6 步。已验证 moves 为实际前进 2 次，actualSteps 为累计走了 4 步。本轮使用一级追问。请在提示中引用 {{moves}} 和 {{actualSteps}}。"}
  ],
  "stream": false,
  "response_format": {"type": "json_object"}
}
```

实施时用结构化上下文生成 `messages`。系统消息明确输出字段、儿童语气、长度上限和当前动作。使用供应商支持的生成上限，初始预算按 512 个输出 token 调整。JSON 模式允许按约定解析，业务结构仍由本地 DTO 和 `guard.py` 校验。成功回复需包含一个完整 JSON 对象。空内容、拒答、截断、额外字段或无法验证的事实进入本地回退。 [结构化输出与 JSON 模式说明](https://developers.openai.com/api/docs/guides/structured-outputs#structured-outputs-vs-json-mode)

### 4.2 模型输入输出和现有接口的映射

第一阶段复用 `decide_with_facts` 和现有动作选择。发给模型的上下文包括课程任务、已验证步骤与动作次数、允许引用的事实 ID、教法意图与提示等级。真实请求使用当前校验通过的运行快照。测试连接从虚构常量构造同样的结构，走同一个解析和输出校验器。

模型负责返回 `message`、`nextStep`、`uncertainty` 和 `factIdsUsed`。事实中的数字和单位由后端生成，例如用 `海龟前进了 2 次` 替换 `{{moves}}`，用 `一共走了 4 步` 替换 `{{actualSteps}}`。使用到的占位符必须与 `factIdsUsed` 匹配。校验器拒绝未授权的引用和模型自行陈述的步数、移动次数等事实，再对替换后的文本做长度和安全校验。交换步数与移动次数的候选回复纳入回归。

后端将已选的 `action`、`answerLevel` 和可用证据字段补入现有响应，生成 `mode: "model"`、`showAsDemo: false` 及本机请求 ID。`learning.anchorBlockId`、`runRequestId` 和 `nextAction` 继续由运行归属和本地决策生成。供应商响应只取结构化内容，浏览器接收经过校验和展开的文案。

```json
{
  "message": "{{moves}}，{{actualSteps}}。再走一轮会到哪里？",
  "nextStep": "看看每轮走几步，试着只改重复次数。",
  "uncertainty": "",
  "factIdsUsed": ["moves", "actualSteps"]
}
```

接口请求经一份运行时配置快照发送。响应可用前复核配置版本。等待期间切换了模型或停用时，课堂使用本地回复并标明配置已改变。真实模型的 `mode` 由后端在通过校验后赋值，配置启用和单条回复成功是两个可独立观察的状态。页面继续用纯文本节点渲染回复。

### 4.3 连接测试与课堂回退

- 连接测试使用「小海龟走六步」的固定样例。积木为重复 2 次、每次前进 2 步，舞台事实为动 2 次、累计 4 步。测试固定为一级提问，要求输出引用 `moves`、`actualSteps` 的简短提示。该测试结果只有在完成真实调用和本地校验后才允许启用。
- 测试请求与课堂辅导各进行至多一次模型调用。保留现有课堂 8 秒上限，连接测试上限 10 秒，覆盖解析和外部 I/O。响应正文上限维持 64 KiB。超时后允许操作者主动重试。
- 模型服务不可用时继续调用现有 `mock`。孩子选择「自己试试」、跳过、或当前证据不足时沿用本地流程。网页采用每条回复的 `mode` 和 `fallbackReason`，避免把已启用的状态展示成单条真实回复。
- 应用级 `effectiveMode` 用于模型设置区。给 `/startup/check` 和课程响应补运行时投影时，保留原有字段结构及 Worker 检查缓存。前端课程刷新不得覆盖已呈现的单条回复来源。

## 5. 同源配置与外部请求边界

网页配置只在单机回环 Demo 提供。配置读写校验实际对端与 `Host` 为回环访问，配置写入同时要求匹配同源的 `Origin` 和 JSON 请求。使用反向代理或公开部署时，模型配置路由应随部署方式重新设计。配置调用使用同源 `frontend/js/api.js`，上游地址和请求始终由 FastAPI 适配器处理。

网页使用的远程地址支持公开 HTTPS 域名及厂商的 API 路径。解析并校验完整地址，拒绝用户名密码、查询串、片段、本机和私有网络目的地。出站传输禁用重定向，连接实际使用已验证的目标地址，TLS 校验使用原始域名。域名解析发生变化时重新核验。可用受控传输层和测试替身覆盖地址校验，现有受运维控制的环境变量网关仍按其旧契约加载。

密钥仅用于构造模型服务请求的授权头。浏览器提交后清空字段，密钥不写入公开 DTO、浏览器持久存储、项目文件、诊断日志或异常。前端保留非敏感字段方便重试。日志沿用白名单投影，只记录本机请求 ID、耗时、结果类别和必要版本。课程测试使用预置示例，不携带当前孩子的程序或对话。 [日志字段](../backend/infra/logging.py)

## 6. 第二阶段多轮教学 Agent

### 6.1 会话和行动权限

在当前 `/api/v1/tutor/hints` 上增加可选 `learningContext.turnId` 和 `learningContext.replyToTurnId`，响应在 `learning` 内增加可选 `turnId` 和 `awaitingAnswer`。保留原来的 `learnerChoice`、`message` 和工作区范围。`turnId` 由浏览器生成，同一提交重试沿用原值。孩子在现有输入框回答时，前端带上当前待答问题对应的回复轮次。服务端只在该问题仍属于当前工作区及运行版本时接续对话。

使用 `(courseId, contentVersion, taskId, workspaceId)` 作为会话范围。在本机内存中保留最近 6 轮问答，设置 30 分钟不活跃过期。每轮只记录提交 ID、提示 ID、程序摘要、运行 ID、经过处理的简短回答、教学动作和待确认问题。更换工作区创建新的范围，普通编辑沿用范围。程序修改后可回顾旧问题的文本，定位和回放须绑定当前版本。助手收到新运行后重新从本地快照生成事实。

| 模型可以选择的动作 | 执行前的条件 | 前端呈现 |
| --- | --- | --- |
| `ask_question` | 问题贴合本题，且下一步能通过回答或动手确认 | 显示一句追问，输入框接续该轮对话 |
| `point_to_block` | 引用当前程序的可定位积木，且目标与本轮证据一致 | 显示「看看这块积木」，由孩子点击高亮 |
| `show_execution` | 运行 ID 匹配且后端验证了轨迹 | 显示「看看怎么走的」，复用回放控制 |
| `hint` | 只给一个当前可做的动作，等级符合课堂策略 | 显示下一步，例如「先预测」或「只改一处」 |
| `offer_variant` | 后端存在可进入的下一题，孩子已完成当前目标或明确选择跳过 | 显示下一题入口，由孩子选择是否进入 |

编辑、运行和切换由孩子在工作台触发。Agent 每轮从预先准备的事实和上述动作中选择一次。后端使用当前程序和运行快照为每轮生成允许动作和引用 ID，模型只返回选择与文案。为完成本期行为，可复用 Chat Completions 和本地会话状态，独立的 Agent 框架属于可选实现。

### 6.2 事实、上下文和结构化决策

- 教学上下文包括本题目标、当前可运行积木摘要、预测与运行结果、核对过的轨迹、最近相关的问答以及本轮可选动作。`factId` 引用教学事实，例如 `moves`、`actualSteps` 和 `firstMove`。`targetRef` 引用可用操作目标，例如 `repeatInput` 和 `verifiedReplay`。这些引用在本机映射为可读事实、实际积木、输入位置和运行 ID。
- 接续回答需匹配当前待答问题。回答很短时允许结合上轮意思理解，例如「我数的是每一步」或「我以为这里是 4」。发送前限定长度并进行儿童输入检查，个人信息、外部链接、完整项目和诊断文本留在外部模型请求之外。连接测试和本地演示全程使用虚构输入。
- 模型可提出对误解的暂时判断，面向孩子的文案使用追问或观察来检验，例如「你刚数的是前进次数还是总步数？」学习总结沿用可验证的课堂记录。动作或事实失去归属、模型拒答或服务失败时，返回适合当前程序的本地提示。
- `guard.py` 的现有决策一致性检查适用于第一阶段。第二阶段以可选动作列表、可引用事实、实际目标存在、提示等级上限和安全文案为准。后端将通过检查的动作映射成现有 `nextAction`。模型不能直接指定运行 ID、实际积木 ID、API 地址或任意代码执行。

```json
{
  "action": "show_execution",
  "targetRef": "verifiedReplay",
  "message": "我们看第一轮。{{firstMove}}。",
  "nextStep": "点开回放，比较移动次数和累计步数。",
  "factIdsUsed": ["firstMove"],
  "awaitingAnswer": false
}
```

### 6.3 提交、重试与失效

每个会话范围同时处理一轮，为 `turnId` 记录进行中或已完成状态。重复提交同一输入返回已有结果或提示该轮仍在处理。同一 ID 的不同输入返回 409。完成后一次性追加已接受的用户输入、助手回复和待答状态，网络等待期间避免持有会话锁。取消或工作区失效时停止应用旧回复。会话记录保存经校验的结果。

客户端发起请求时捕获课程版本、任务、工作区、程序修订号、运行 ID 和主要请求顺序。异步响应只更新当前请求。修改、换题、开始新运行或停用模型后，关闭属于旧尝试的定位或回放按钮。提示账本继续按 `seenHintIds` 记录实际呈现的提示，同一轮重试复用原提示 ID。

### 6.4 示范对话

在「小海龟走六步」中，设置重复 2 次、每次走 2 步。孩子预测会动 4 次，舞台实际记录为动 2 次、走 4 步。模型先问「你刚刚数的是前进次数，还是总步数？」

| 孩子的回答 | 老师接着怎么教 | 验收观察 |
| --- | --- | --- |
| 「我把每一步都算成一次移动。」 | 提议回放第一轮，解释一次前进可以走两步 | 返回 `show_execution`，按钮播放本次运行，说明与轨迹相符 |
| 「我以为重复积木那里填的是 4。」 | 定位重复积木，问「你现在看到的次数是多少？」 | 返回 `point_to_block`，定位当前重复积木，孩子可以实际核对 |
| 孩子改动了重复次数，然后重新运行 | 用新快照确认移动次数、步数和目标状态 | 旧回放关闭，新的问答与新结果匹配 |

两个回答使用相同的题目、程序和舞台结果。通过条件是两条分支都引用真实事实，且动作确实不同。模型的中文句式可以变化。

### 8.2 真实模型和浏览器验收

1. 在本机启动 Demo，进入「系统信息 → 模型接入」。用虚构循环题测试真实 API，确认测试返回成功、展示耗时和可用模型，密码框已清空。
2. 启用后进入「走六步」，让海龟实际动 2 次、走 4 步。点求助并查看来源。第一阶段的通过条件是 `mode="model"`、无回退原因、提示准确引用本次事实，并保留原有定位、回放和继续练习流程。
3. 用无效密钥测试一次，确认原来的活动配置保持生效。用测试替身模拟一次已启用模型在课堂超时，确认该条回复降级为演示。切回演示模式后，下一条求助正常响应。
4. 在 Chrome 和 Edge 复验 1280×720 与 1024×768 的面板，核对键盘焦点、状态提示、密码输入、错误重试和回退标签。
5. 实施第二阶段后，分别用两种虚构回答完成第 6.4 节。检查模型能给出各自适用的下一步，修改之后旧回放失效，且两种场景都能继续完成练习。

验收记录分开填写模拟传输和真实端点结果。真实验收填写模型名、连接测试结果、提示来源、是否引用正确事实和可能的故障分类。密钥、请求正文和孩子的原始输入不进入验收记录。

## 9. 发布和恢复

第一阶段使用本机 Demo 发布方式，网页配置随进程释放。交付前更新[运行说明](run.md)、[接口契约](api-contract.md)和[演示脚本](demo-script.md)，写清 API 基础地址形式、配置生命周期和真实回复的判定方法。真实模型出现问题时，页面的「使用演示回复」可立即恢复本地课堂。正式回退代码时同步复验旧环境变量网关、预测、运行、提示与学习总结。

第二阶段增加可独立切换的应用配置 `CMK_TUTOR_AGENT_ENABLED`，默认沿用第一阶段策略。开启后，只有启用网页模型且当前请求满足会话归属时才进入多轮决策。出现教学动作或延迟回归时，关闭多轮策略并恢复到已验收的第一阶段策略。保留阶段各自的验收记录，用户可据此判断已经验证的是模型联通、课堂提示还是多轮教学。

# 工具箱拖放与 Scratch 式嵌套体验修改指南

> **状态提示（2026-11-18）：** 本文是早期交互审查，之后代码已加入部分放置目标、容器分层绘制、pointer cancel 和事务拖放实现。最新的当前代码复核、仍待修复项和浏览器验收步骤见[积木拖放恢复方案](interactive-blocks-recovery-plan.md)。阅读当前实现状态时以新方案为准。

> 适用版本：CodeMateKids 0.1.0  
> 目标：修好工具箱积木的可发现、可放置、可插入和可编辑体验，并让循环及表达式嵌套在视觉和操作上都能看懂。继续使用项目自研编辑器，不要求嵌入 Scratch/Blockly。

## 结论

当前拖放并非完全没有接通：工具箱通过 Pointer Events 启动自定义拖动，动作积木可以放进现有循环体。不过，落点规则很窄，部分工具箱积木根本没有合法落点；循环容器还会把内部积木盖住并截获点击。因此用户会感到“拖不动”或“嵌套不像 Scratch”。

编辑器的核心已有树模型、端口规则、撤销/重做和 Canvas 画布。问题集中在放置目标设计、绘制/命中顺序和表达式节点呈现。改造时应让可放置区域、画出来的插口和底层树操作使用同一份连接语义。

## 可借鉴 TurboWarp 的交互原则

参考页面：[TurboWarp 编辑器](https://turbowarp.org/editor)。本次查看了编辑器的分类栏、积木列表、脚本工作区、角色舞台和控制/运算积木形态；以下是对可见交互的归纳，不是对 TurboWarp 内部实现的审查。

| 观察到的交互 | 对 CodeMateKids 的建议 |
|---|---|
| 积木按功能类别筛选，当前类别清楚标记；同类积木在独立列表里滚动浏览 | 按课程中的“开始/动作/循环/数值”等少量类别组织工具箱，选中类别有文字和图标状态。当前主题只显示课程允许的积木，不必一次提供 Scratch 的全部类别 |
| 普通动作可以首尾拼接，控制积木用 C 形槽表达“把动作放在里面” | 为语句块设计统一的凸/凹连接边，为循环设计清晰的内嵌槽和侧壁。连接形状要与实际端口规则一致；容器内部背景不能遮住孩子积木 |
| 数值块呈圆角/椭圆形，布尔块用不同轮廓，嵌进字段时保持内嵌形态 | 在未来开放表达式时，为值和条件创建独立轮廓及真实递归插槽；当前课程没有接收槽的值积木应隐藏，不显示“看起来能用却放不进去”的部件 |
| 舞台预览与脚本编辑区域并列，脚本区有网格和缩放控件 | 保留 CodeMateKids 自己的课程和角色预览，把画布滚动/缩放做成可理解、可重置的独立操作；小屏时明确哪些面板折叠，不照搬 TurboWarp 的完整舞台/角色管理区 |
| 积木内部参数可直接点击编辑，插槽和连接关系由形状表现 | 保留直接编辑参数的便利，并增加悬停/拖动时的目标高亮、插入线、非法连接原因和松手后的吸附反馈；不能只依赖颜色告知是否合法 |

### 只借交互，不复制外观

不要复刻 TurboWarp/Scratch 的商标、角色、素材、图标、逐字文案、精确配色、积木外轮廓细节、面板比例或完整屏幕布局。可以沿用行业通用的类别筛选、形状表达连接类型、循环容器与插槽、画布缩放和吸附反馈，但请自行设计 CodeMateKids 的配色、圆角/连接几何、图标、字体、间距和儿童提示文案。优先服务本项目“一次处理一个学习目标”的流程，不追求与参考页面功能数量相同。

推荐的本项目视觉方向：沿用现有柔和底色和课程卡片风格；用自有的积木色板与小型类别选择器；用独特的圆角梯形/侧边纹理表达语句类别，控制块以明确包围语句体的 U/C 形轮廓表达嵌套；输入槽用内凹背景和占位说明表达可放置类型。颜色只作辅助，积木文字、轮廓、插槽标签和无障碍名称共同说明用途。

实施时先修复下列可见性、命中和放置逻辑，再做样式打磨；否则即使画得像参考编辑器，内部积木仍会被覆盖或拖动后落错位置。

## 已确认的问题

### 1. 循环里的积木被容器遮挡，也很难单独选中

相关位置：[layout.js](../frontend/js/editor/layout.js#L90)、[render.js](../frontend/js/editor/render.js#L98)、[render.js](../frontend/js/editor/render.js#L127)、[layout.js](../frontend/js/editor/layout.js#L152)

`layoutBlock()` 先递归记录循环体的子积木，最后才把循环父积木加入布局数组。`drawScene()` 按数组顺序绘制，父积木又用整个矩形填充背景，于是它会覆盖先画好的子积木。命中测试反向遍历同一数组时，父积木的包围框也先截获点击。结果是：即使积木已经挂进 `control.repeat.body`，也可能看不到或选不中。

修改建议：把“容器外壳/头部”和“子积木”分层绘制。先绘制容器背景和凹入的语句体，再绘制语句体中的子积木和连接轮廓；不要在子积木之后用父容器整块不透明填充覆盖它们。命中判断优先选中当前指针下最深层、最具体的可见积木；容器标题区命中容器，语句体中已经显示的孩子命中孩子。布局、渲染和命中继续共享同一套几何信息。

验收标准：循环内动作清楚可见；点击动作可选中/拖动动作，点击循环标题可选中/拖动循环；嵌套两层时内外层均可分别操作。

### 2. 放置区域太窄，画布空白和块间插入没有明确行为

相关位置：[dnd.js](../frontend/js/editor/dnd.js#L73)、[dnd.js](../frontend/js/editor/dnd.js#L84)、[layout.js](../frontend/js/editor/layout.js#L129)、[layout.js](../frontend/js/editor/layout.js#L152)

拖动由自定义 `pointerdown/move/up` 实现，不是浏览器原生 HTML Drag and Drop。释放时只接受距离现有槽位 24px 内的目标；非空画布没有通用空白放置目标，语句拖进循环体也只会追加到末尾。用户看不到清晰的“插在这里/放进这里”提示时，稍微偏离目标就会被拒绝。

修改建议：不要仅给工具箱按钮增加 `draggable` 或 `dataTransfer`。先明确三种语句放置意图：空程序的根位置、已有语句之前/之后、容器的空语句体/语句之间。让 `layout` 为这些目标生成稳定的 target ID 和较宽命中区；预览状态显示与释放位置一致的插入线、容器高亮和连接形状。空白释放时按产品规则插入到最近的合法位置，或给出直白说明，不要静默取消。

`model.js` 的 `attachToBody()` 目前始终把新语句追加到语句体尾部。建议让 drop target 携带明确的插入索引/相邻 block ID，使拖进非空循环时可以插到任意子块前后；移动现有积木时先从旧位置摘除，再按目标位置插入。表达式和值积木仍只能进入类型匹配的表达式槽，不能作为语句插入。

验收标准：空画布、已有语句之间、循环体为空及循环体已有多个动作四种情况均能预测性放置；有效目标在拖动时明显高亮；用户可将动作插到两个已有动作之间，而不只是追加到尾部。

### 3. 当前课程显示了没有合法落点的值积木

相关位置：[course.json](../content/demo-loop/course.json#L53)、[blocks.v1.json](../schemas/blocks.v1.json#L214)、[layout.js](../frontend/js/editor/layout.js#L59)

两个任务的工具箱都允许“数字”和“算一算”，但当前任务没有 `text.print` 这类带表达式字段的语句块；主程序布局中表达式槽数量为 0。两个值积木因此无法合法投放。工具箱显示了可拖动按钮，却没有可用目标，会直接强化“积木拖不动”的感觉。

修改建议：本轮课程若不需要表达式积木，就从两个任务的 `allowedBlockKinds` 中移除 `value.number`、`value.calc`，同时保留 schema/能力定义供未来课程使用。若课程确实要教表达式，则在同一迭代中提供带表达式槽的可运行积木、初始程序示例、表达式渲染/命中/编辑和后端执行路径，再把值积木放回工具箱。不要仅为了让积木“有地方放”而放宽端口校验。

验收标准：每个可运行工具箱积木至少有一个当前任务中能找到的合法落点；无法使用的积木不应显示成可拖动按钮。

### 4. 表达式树目前只作为文本显示，不是真正嵌套的积木

相关位置：[layout.js](../frontend/js/editor/layout.js#L59)、[render.js](../frontend/js/editor/render.js#L41)、[render.js](../frontend/js/editor/render.js#L196)

表达式字段只布局一个矩形槽，`value.calc` 的左右输入递归转成文字标签，不会为表达式子节点创建独立布局、插槽或命中区域。把“算一算”放进值槽后，用户看不到算式里还能继续嵌套数字，也无法直接选中、替换左右操作数。

修改建议：需要表达式编辑时，将递归表达式布局纳入统一布局结果，为每个表达式节点创建独立矩形、输入槽和命中项；`expressionLabel()` 可用于代码摘要，不能代替交互式树渲染。拖入子表达式、替换输入和移出节点都要通过树事务更新。若近期不实现递归交互，应先隐藏当前课程不用的表达式积木，避免展示半成品能力。

验收标准：嵌套表达式的每个节点都可见、可命中和可替换；拖放只接受类型正确的左右输入；无效放置保留原表达式结构。

### 5. 表达式放入字段时会写入后端不接受的额外字段

相关位置：[model.js](../frontend/js/editor/model.js#L203)、[program.py](../backend/domain/program.py#L18)、[program.py](../backend/domain/program.py#L142)

表达式挂接时，模型把字段名写到表达式节点的 `node.fieldName`，同时也已把该节点放入拥有者的 `inputs[field]`。后端节点 schema 只允许 `blockId/kind/inputs/body/next/unknown`，所以这个多余字段会令后端以 `PROGRAM_SCHEMA_INVALID` 拒绝运行。

修改建议：删除表达式节点上的 `fieldName` 写入；字段关系只由父节点的 `inputs[field]` 表示。同步检查序列化、剪切/移动和表达式插槽替换路径，不要在其他地方重新添加该临时字段。

验收标准：将数字表达式接入带 expression 字段的积木后，序列化 JSON 可通过后端 `validate_program()`，运行接口不再因 `fieldName` 报 schema 错误。

### 6. 拖放失败可能修改原程序，取消拖动也缺少完整清理

相关位置：[model.js](../frontend/js/editor/model.js#L182)、[model.js](../frontend/js/editor/model.js#L203)、[dnd.js](../frontend/js/editor/dnd.js#L73)、[dnd.js](../frontend/js/editor/dnd.js#L136)

`applyDrop()` 对移动节点先在传入的原树上执行 `detachBlock()`，之后才确认目标 owner/连接有效。后续失败时虽返回 `ok: false`，原树可能已被摘除节点。拖放控制器还没有统一处理 `pointercancel`、指针 ID 和窗口失焦，手势被系统取消时可能留下预览或监听器。

修改建议：移动操作在克隆树或不可变副本上完成摘除、连接校验和挂接，全部成功后才一次性替换状态并记录一次撤销事务；失败保证原树字节级不变。拖动记录 `pointerId`，只响应起始指针；将 `pointerup`、`pointercancel`、`lostpointercapture` 和窗口失焦接入同一清理方法，保证预览、监听器和拖动状态都释放。

验收标准：不存在的目标、类型不匹配、循环引用和取消手势均不损坏程序，也不遗留拖动预览；成功移动仅生成一个撤销步骤，撤销/重做后结构准确恢复。

## 建议实施顺序

1. **先让基础拖放可预测**：处理根/块间/语句体落点、扩大并可视化命中区；暂时从当前课程隐藏没有合法目标的值积木。
2. **修好循环嵌套**：分层绘制容器与子块；按最深可见节点命中；增加子块之间插入位置。
3. **保证数据正确**：拖放事务化，失败原树不变；移除表达式节点多余的 `fieldName`。
4. **再补表达式积木**：仅在课程有明确教学需求时实现递归布局、拖放、命中和运行测试。
5. **完成输入设备与视觉打磨**：补指针取消清理、积木拼接形状/插入指示及键盘等价操作。

## 回归验收清单

- 从工具箱拖出动作积木，成功放入空程序、顺序链和循环体。
- 在顺序链或循环体的两个动作之间插入积木，前后位置符合预览指示。
- 循环内子积木绘制在容器内部并可独立点击、拖动、编辑和删除；点循环标题只操作循环本身。
- 工具箱类别表达简洁、当前选择可见；拖动时目标槽、插入线和非法原因清楚，视觉采用 CodeMateKids 自有样式，不复刻 TurboWarp/Scratch 的完整界面。
- 所有显示在工具箱中的积木至少存在一个当前任务中的合法落点；非法端口组合有清楚反馈，不改变树状态。
- 失败放置后程序树、撤销栈和画布视图均保持原状；一次成功拖动只需一次撤销即可还原。
- 在触屏/触笔或模拟 `pointercancel`、`lostpointercapture` 后，拖动状态与预览均清除；鼠标仍可正常拖放。
- 若开放表达式积木，嵌套表达式可逐节点拖放编辑，并通过后端程序校验和运行。
- 浏览器手工验收至少覆盖 Chrome/Edge、1024×768 与 1280×720；`node tests/js_editor_check.mjs` 和后端 `python -m pytest tests -q` 通过。
